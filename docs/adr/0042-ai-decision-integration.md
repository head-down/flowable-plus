## 上下文

### 主仓现状与基线

主仓 `flowable-plus` 已发布 1.0.0 GA，基线 **Java 8 + Spring Boot 2.7.18 + Flowable 6.8.0**。

现有的 `AutoApprovalRule` SPI（ADR-0008）把「决策」与「执行」焊在**同一条**路径上：`startProcess` 事务内**同步**拉规则 → 返回 `String` → **立即自动提交**；异常即 fail-fast，配合事务使流程创建与自动提交原子回滚。它是**拉**的、同步的、单层的、fail-fast 的。

### 立项命题（可证伪句）

> 框架缺少一个**公开且契约化**的位点，使在流程实例之外形成、**于实例存在后异步到达**的决策，在进入流程时，其**依据、出处与主体**能够以框架契约承诺的方式留存，并与流程状态共享同一一致性承诺。

两处措辞是承重墙，不得松动：

- 「**公开且契约化**的位点」——命题**不主张**「没有地方放」，而主张「没有**框架承诺**的放法」。应用用通用 BPMN 原语 + 注释 + 变量**能拼出**功能等价的链路，但那不是契约承诺。
- 「**于实例存在后异步到达**」——这是「决策与执行分离」的**定义性前提**，不是可选形态。一旦要求决策必须在流程启动前到手，它就不再是分离，只是「应用算完一个值再启动」。

命题只列 **依据 / 出处 / 主体** 三项。时间维度、失败可容错、结构化载体三项**不进命题** —— 它们可被应用侧以通用 BPMN 原语达成，写进命题等于给反例递刀。

### 判据与两条 kill switch

**主判据 A —— 「有契约承诺的值」**：应用侧表达同一件事时，是否必然丢失某项**由框架契约承诺的**契约属性。属性的完整形态 = **有值 + 由框架承诺**（在失败 / 回滚 / 重试 / 覆盖 / 续跑下仍成立，不依赖应用自觉）。**D**（与既有机制结构上互斥）为优先举证形态；**B**（多方重复实现）、**C**（监管强制义务）仅辅助，不单独成立。

**kill switch 1（升级版）**：反例存在即主张作废，但反例必须**同时**满足五条 ——

1. 使用框架**公开且契约化**的位点；
2. 依据 / 出处 / 主体能被**第三方稳定识别**；
3. 不依赖应用**私有 JSON / 私有命名 / 私有表 / 私有补偿**；
4. 在**失败、回滚、重试、覆盖、续跑**场景下，框架承诺该留痕与流程状态一致；
5. 后续**审计 / 排障 / 监管**视角可不依赖实现方内部知识而直接验证。

仅满足「应用可以把 JSON 塞进注释 / 自建表 / 自己保证一致」的反例，**不算击穿**。

**kill switch 2**：证明不了**边界可控**就退回。它已被立为**可判定闸门**（见「决策」第 13 节），判定对象是三条承重边界的四条承重不变量能否被**主动击穿实验**判定，**不是**「验收矩阵全绿」。

**两条 kill switch 保留**：① 写不出「框架缺什么」、只能写出「我想加 AI」→ 退回「不做或只做示例」；② 证明不了边界可控 → 同上。

### 落地模式与边界前提

- **模式**：P3 审批助手为主 + P1 证据生成器为辅 + P2 自动决策**默认关**（仅作受控压力测试探针）；核心机制 = **决策证据 + 人工覆盖留痕**。
- **落点**：机制进 `flowable-plus-extension`；下游接入方仅做接线验证；**不新建** `flowable-plus-examples`。
- **技术栈**：主仓保持 Java 8；另起 Java 17 沙盒（**并列，非升级**）。
- **执行位置**：外部实时调用**不进** `startProcess` 事务、**不进** `AutoApprovalRule` 同步路径。
- **原 SPI 契约不动**：不修改 `AutoApprovalRule` 的 `String` 返回契约。
- **失败负空间**：不允许**静默通过**；不允许**无证据自动提交**。
- **数据边界**：泄密红线已解除，但出域白名单 / 脱敏 / 摘要 / 截断仍是设计需求。

来源：探索期决议（接缝、依赖形态）。

### 外部形态参照（Java 17 沙盒）

成熟框架里的「同一件事长什么样」由沙盒取形态证据，**只作参照、不构成前提**（ADR 可引用、不等待）：

- **接缝位置与粒度**：闸门在**编排层**、粒度**节点级**（部署期静态声明）；人工输入 = 外部直接改图状态，**在节点身份里没有自己的位置**；中断元数据不在元素流里，而是生成器的完成值（只看元素流会把中断静默当成正常结束）。
- **挂起—续跑**：状态在 checkpointer，**进程不必活着**；`releaseThread` **默认 `true`**，会把「可原地续跑的那一份」归档掉；`getState` 与 `lastStateOf` 不等价。
- **证据 / trace 的组织**：框架的执行结果分类闭集里**没有「决策证据」**；持久单元字段闭集仅 `{id, nextNodeId, nodeId, state}`，留痕下限项只能作**普通状态值**；通用元数据袋**不落盘**且与投递 / 读取两面**两处静默不对齐**，「为何停下」不在盘上。
- **错误降级与退出接缝**：重试是**节点级部署期 hook**、中间尝试不留痕；失败走**带外抛出**（完成值 `EMPTY`、状态不推进）；`cancel` **只终止迭代、不终止编排**。

**已知张力**（只记录，不改结论）：`langgraph4j-core-jdk8` 最后版本停在 1.1.5（2024-12-14），此后停更近两年，远落后主线 —— 与「Java 8 下无成熟 agent 框架」的判断同向。

来源：探索期决议（沙盒形态与边界、沙盒执行）。

## 决策

### 1. 接缝成立，命题写成可证伪句

接缝**成立**：框架确缺一个公开且契约化的位点（命题见「上下文」）。逐条对账本节给出的 7 条事实差距：

| 差异 | 判定 |
|---|---|
| ① 时间维度（挂起—续跑） | 独立机制主张**关闭**（见「不做 / 已知边界」）；事实面保留为命题前提 |
| ② 覆盖范围（单点 → 节点级） | 可绕过：就发起人首任务一层而言，现契约本已覆盖 |
| ③ 失败可容错 / 可分派 | 可绕过：外部调用失败则应用不调 `startProcess`，fail-fast 无从谈起 |
| ④ 结构化载体（`String` → 结构化对象） | 可绕过，且被「原 SPI 契约不动」排除 |
| ⑤ 确定性 | 不构成框架问题：框架视角拿到的是一个确定的返回值 |
| ⑥ 留痕（依据 / 出处 / 主体） | **构成缺口** —— 但仅在「契约承诺」判据下成立 |
| ⑦ 主体归属 | 并入 ⑥ 的「主体」一项 |

**已知弱点**：命题成立**依赖判据修正**（A 由「有值」修正为「有契约承诺的值」）；若判据退回「仅问属性是否有值」，命题即被推翻。通用 BPMN 原语足以让应用拼出功能等价的链路，但不构成契约承诺 —— 这是本命题最容易被质疑为「移动球门」的一点，如实记录。

来源：探索期决议（接缝）。

### 2. 契约面：新增「建议提交」，与原 SPI 互补而非并列

在**不改** `AutoApprovalRule` 的 `String` 契约的前提下，新增一套**「建议提交」契约**，只服务 **P3 建议链路**（外部 / AI 作助手，人保有决策权）。

对「并列 / 包裹 / 独立于自动提交链路」的正面回答：**三者都不是** —— 它是**互补的另一半机制**。

- 原 SPI 是**拉**：`startProcess` 事务内同步拉规则 → 返回 `String` → **自动提交**（决策进执行）。
- 新契约是**推**：外部在自选时点提交「建议 + 依据」→ **只留痕，不推进流程**（决策进留痕，待人裁决）。

**契约面清单**：

| # | 契约面 | 职责 | 归属 |
|---|---|---|---|
| 1 | **位点服务** | 接收「一条建议提交」；推契约本体 | extension，独立接口注入，**不进 `FlowablePlus` 门面**（ADR-0010） |
| 2 | **建议提交模型** | 一体提交：建议动作（必填）+ 依据（显式状态） | extension |
| 3 | **依据值类型** | 独立公开值类型；结构位置契约化 | **写入契约**在 extension；**共享值类型住 core** —— `DecisionEvidenceVO` / `DecisionRationaleFact` 及其取值枚举是 core 读侧字段 `decisionEvidences` 的元素类型，core 不能依赖 extension（2026-09-25 显式化，见头部登记 ①） |
| 4 | **拉管线** | 可选生产件：装配上下文 → 调 provider → 产出建议；**只生产、不执行** | extension |
| 5 | **`TaskCreatedEvent`** | 拉管线的到点信号（core 侧唯一增量） | core |

**九条定案**：

1. **链路**：契约锚定 P3；结构化决策结果**不引入** core 自动提交链；P2 继续用 `AutoApprovalRule` 作探针。
2. **驱动方向**：**推为主契约；拉为可选生产管线**（只生产、不执行）。
3. **原子单位**：**一条面向指定审批上下文的建议提交**，含建议结果与**显式依据状态**。一体提交 —— 不拆结果 / 证据双通道，不引证据后挂集合。
4. **建议动作词汇**：复用 core `ApprovalAction` 的**表态比较面**（取值域由人工覆盖决议收紧，见第 12 节）；**建议动作必须与当前任务可用投票动作匹配**（校验规则，非文档约定）；不允许无动作、仅证据提交。
5. **归属与装配**：**写入契约**（位点服务 / 建议提交模型 / 拉管线 / 出域策略）全住 extension；**core 不新增写入契约类型**；**读侧承载类型住 core**（`DecisionEvidenceVO` 及其取值枚举与 `DecisionRationaleFact`，见第 11 节第 4 条账本第 ③ 行）；starter 以**对 extension 的 optional 依赖 + `@ConditionalOnClass` 条件装配**接入（与既有 `spring-security-core` / actuator 可选集成同构）。
6. **依据的类型位置**：依据是**独立公开值类型**，有固定结构位置；字段、状态枚举、可空性、扩展方式见第 5 节。
7. **隔离边界**：与 `AutoApprovalRule` 自动提交链路**完全隔离** —— 不实现、不提供适配器、不桥接、不在 starter 装配任何「建议 → 自动提交」通路。
8. **拉管线入口**：`TaskCreatedEvent`（到点信号）+ **节点级显式声明**（必须）+ **事务外异步执行**。事件回调**禁止直接调模型**；模型调用必须在流程事务之外；**失败必须显式可见**。
9. **事件覆盖范围**：`TaskCreatedEvent` 只在 **flowable-plus 受控入口**发射（`startProcess` 后，以及每次审批操作使新待办就绪时）；**不覆盖**引擎驱动创建（定时器边界、异步续跑、消息事件、子流程派生）。命名沿 core 既有惯例（既有 9 个事件同形：「语义事实名 + 受控入口覆盖」）；**覆盖契约写在类型 javadoc 与 ADR，不写在名字里**。

**与 ADR-0015（公开 API 准入）的关系**：准入判据「领域增值」由两条承担 —— ① 建议动作复用 core `ApprovalAction` 词汇（契约说的是本框架的语言，不是外来 JSON）；② 依据有**契约化的结构位置**。用 `Map` / 裸 `String` 承载依据会让「去掉透传后方法体空白」，正撞反模式。

**「可选」的准确含义**：不引 extension → 零 Bean、零行为变化；未做节点声明 → 拉管线不触发；不提交建议 → 审批任务流程完全不受影响。

**已记的债**：`ApprovalAction` **白名单漂移** —— 白名单留在 extension，词汇所有权在 core；core 未来新增投票动作时 extension 不会自动跟随，**用 extension 侧枚举守卫测试管理**（不通过在 core 放「无消费者的常量」来消除漂移，那撞 ADR-0030）。

来源：探索期决议（C′ 扩展契约形状）。

### 3. 决策源中立与通用化

**总纲**：通用化**不是新增抽象，是把既有契约的中立性承认下来并钉死**。能通用的是**推面**（位点服务对生产者无来源要求）；**拉面天然收敛**（只有「决策目标」一个概念，且它不代表决策源）。

- **接缝判据 = 外部性 + 决策时刻不受框架控制**，**不是「非确定性」**。「非确定性」是生产者的自述、第三方不可核查（撞 kill switch 1 条件②），且会把「外部确定性规则服务 / 离线批算」挡在门外。
- **抽象层级 = 零新增**：不为「决策源」开一等类型、不开注册面、不开 SPI。决策源的全部消费者 = 证据的 `subject` + 可观测信号维度，二者已存在。
- **取值面闭集**：`subjectType` 保持三值 `AI / SYSTEM / USER`，**扩展必须走框架发版**。三值是**语义上位**而非实现枚举（模型类 = `AI`；离线批算 / 外部规则服务 = `SYSTEM`；人 = `USER`）。
- **判别式 = 允许「有决策源、无决策目标」的提交**（下称**直提**）。位点服务的准入**不得**要求「可归因到某个决策目标」—— 人可在系统外决定后提交、离线批算可直提、框架内规则可直提。若不允许，机制在契约上就等价于「所有决策都必须是框架发出的一次外部调用的产物」，ADR 便写不出「框架缺什么」。

由判别式派生的四条：

1. **证据面新增「无外部调用直提」产出情形**：`subject`（`subjectType` 必填）承载出处；**出处组可空或不适用**；**不得**用既有 `chainStage=rule` 或占位 `provider` 硬凑。**直提列 `modelId` 必须 null** —— `modelId` 描述的是 **provider 契约事实**（框架可证实的出站调用产物），直提无 provider，框架无从证实；直提方若要自报模型，走 `BASIS_CODE` / `SOURCE_REF`，不由 `modelId` 兼职（2026-09-25 显式化，见头部登记 ②）。
2. **可识别性靠结构、不靠新字段**：第三方由「**出处组为空**」唯一推出直提，守卫测试钉死这一**双射**。**「出处组为空」= `provider` ∧ `chainStage` ∧ `degraded` 三者全为 null**（全组语义）；据此 `degraded` 取**可空 `Boolean`** —— 原始 `boolean` 永不为 null，「出处组为空」将永不成立，双射失效（2026-09-25 显式化，见头部登记 ②）。**「直提性」永不落标识符**：不得新增 `direct*` 一类字段 / JSON 键 / 枚举取值。
3. **直提不适用装配位点与出域位点**（载荷由提交方交上来，框架既不装配、也不出域），**但适用**入站载荷卫生与硬上限 clamp。**数据源声明在直提下退化为提交方自律** —— 框架无从核查，改由可选**自述位**承载。此点必须写明，否则通用化会顺手掏空出域控制。**方向后果（2026-09-25 显式化，见头部登记 ②）**：提交方交上来的载荷是**入站**载荷 ⇒ 直提的**出域**方向恒为「无实际载荷」（`outboundCompleteness = NO_PAYLOAD`），**入站**方向按提交方是否交载荷取 `FULL` / `PARTIAL` / `NO_PAYLOAD` —— **不是**一律 `NO_PAYLOAD`。
4. **直提准入失败必须可见**：同步抛 + **同一次失败物质化为 `SUGGESTION_FAILED`**（**物质化的宿主与判据见第 8 节第 4 条** —— 宿主 = 位点服务自身、在抛出之前落行；带齐**三项前置**〔`taskId` ∧ `idempotencyKey` ∧ `subjectType` 皆非空〕才落行，缺任一则退**日志 + 指标**、不落行，三项的逐条理由见第 9 节第 9 条）。**（2026-09-26 显式化，见头部登记）** 原句「唯一例外是缺幂等身份」**收窄失效**：例外面由「一项」扩为「三项前置」。**要求本身（直提准入失败必须物质化）未动**，被改的只是例外子句。

**推面与节点声明解耦**：节点四个决策属性没有一个是推面需要的（它们是拉面触发门控、执行对象、出域策略、装配声明）。推面的门控**只有一条**：建议动作须与任务可用投票动作匹配。若让声明也门控推面，则每个可直提节点都必须写 `decisionTarget` —— **「无目标提交」在部署期就配不出来**。

**v1 可达性**：v1 **不交付任何公共的非 AI 生产件**，但**测试内**必须提供最小 `SYSTEM` 直提生产者桩，且**同时覆盖 `USER`** —— 否则「人可作为决策源」是纸面的，撞 kill switch 1。

**中立性核对清单**（「契约不预设 AI」必须可核对，覆盖五面）：① 类型与常量命名不绑 AI（`DECISION_EVIDENCE` 一类）；② 取值域不绑 AI（`subjectType` / `chainStage` / `outcome`）；③ 必填性不预设「必定经过模型调用」；④ **依赖方向**：extension / starter 的依赖图上不得出现任何 AI 相关依赖；⑤ **装配**：starter 条件装配不得装配任何 AI 组件。①–③ 靠契约 / 枚举 / 可空性守卫测试；④–⑤ 靠依赖图与装配断言，**⑤ 尤其承重** —— 它把「AI 只是众多生产者之一」从文档承诺变成装配事实。

**命名**：节点属性 `decisionSources` → **`decisionDataSources`**（原名与术语「决策源」同词根、近读法，实指装配面的业务数据上下文来源）。**命名约束（钉死）**：同一元素上**不得并置只差一个 s 的形近属性名**；若将来要显式声明决策源，**绝不得**新增 `decisionSource` 属性。

来源：探索期决议（通用化）。

### 4. 技术底座与依赖

**依赖形态：裸 HTTP 自建，不引厂商 SDK。** 理由不是「没得选」，而是**厂商中立是框架级约束** —— 引任一厂商 SDK 等于框架替下游做厂商选型。

| 层 | 选型 | 依赖成本 |
|---|---|---|
| JSON | Jackson（`com.fasterxml.jackson.*`） | **零新增**（`flowable-engine` 已 compile 传递 `jackson-core` / `jackson-databind`） |
| HTTP | `org.apache.httpcomponents:httpclient` **4.5.14** | 新增 1 个库；**版本由父 POM 的 `spring-boot-dependencies` BOM 管** |
| 流式 | v1 不做 | — |

**v1 不做流式（SSE）**：机制本体属请求-响应型；流式与「决策证据快照」天然冲突（半截响应不能当证据）；延迟由异步消化；流式属表现层，归下游在 provider 缝之后自行实现。

**对 ADR-0029 判据的影响**：**判据 1（依赖隔离）为主，判据 2（可选领域能力）为辅** —— 引入 Apache HttpClient 即满足判据 1。

**被推翻的论证**（如实记录）：建图时曾写「core 已含 Hutool → 裸 HTTP 引入零新依赖 → 判据 1 不成立，只能走判据 2」。该论证**作废** —— 「零新依赖」不是论据，是账本上的一行：基线本就挂着 `hutool-all`，而全项目只用了 3 处、全是 `StrUtil`，该能力 commons-lang3 `StringUtils` 直接覆盖（commons-lang3 已在 classpath）。**依赖账本该比总质量，不比增量条数。**

**事实更正**（一手核实）：厂商官方 Java SDK（OpenAI / Anthropic / 百炼）当前版本**均支持 Java 8**，故「唯一可行路径是裸 HTTP」的原表述不成立；不采用的理由是**锁厂商**，不是不可用。

### 5. 决策证据：单一审计面 + 只读证据组

**落点 = 单一审计面 + 只读决策证据组。** 证据**不另开接口、不自建表、不伪装成人工审批意见**；它进 `getApprovalHistory`（ADR-0028 唯一读入口），以**独立字段**出现，**不占人工意见槽位**。

对「沿用流程注释？扩审批轨迹 VO？新增表？」的正面回答：**沿用流程注释的存储，扩审批轨迹 VO 的出口，不新增表** —— 三者各取其一，而非三选一。

**为什么不能开第二审计面**（三条否决）：① kill switch 1 条件⑤ 只在单一审计面上可证（另开接口则审计者必须知道两处，正是 ⑤ 要排除的实现方内部知识）；② 第二张表会是框架史上第一张自建表（全仓零 DDL / 零迁移，且新表要接 ADR-0014 多库 CI）；③ 与本仓演化留痕的既定手法不同构（既定手法 = 扩 `CommentType` 分组 + 扩 VO 字段，不动存储）。

**物理承载**：`ACT_HI_COMMENT`；载荷 = **纯前缀标记** `[SYSTEM:DECISION_EVIDENCE]` + JSON。

- `FULL_MSG_` = 标记 + 完整 JSON —— **这是唯一被公共读路径显示的列**（`Comment` 接口无 `getMessage()`；官方 REST 取 `getFullMessage()`），视觉屏障落在正确的地方。
- `MESSAGE_` = 标记 + 折叠截断（≤163 字符）后的 JSON —— 公共读路径取不到，契约中当作不存在。
- 否决「JSON 首字段」形态：截断后会变成损坏 JSON；纯前缀截断后前缀仍完整，读侧 `startsWith + substring` 也更健壮。
- **载荷必须 ASCII-safe**（Jackson `ESCAPE_NON_ASCII`）：`FULL_MSG_` 的写入走平台默认字符集，而 BLOB 是裸字节、DB 不重解释 —— 写读环境字符集不同会 mangle 中文，转义后免疫。
- **标记与 `TYPE_` 必须同源**（一个常量 + 守卫测试）：常量类 `DecisionEvidenceComment`（与 `CommentType` 同包）承载 `MARKER_PREFIX` / `MARKER_SUFFIX`（**私有**）、`marker()`、`hasMarker(String)`、`stripMarker(String)`，由 `CommentType.DECISION_EVIDENCE.name()` 派生 —— 标记**构造来源唯一**，写侧读侧都无法自行拼装。**标记与 JSON 之间无分隔符**（`marker()` 之后紧跟 JSON），剥离判据 = `hasMarker()` + `stripMarker()`（JSON 必以 `{` 开头，与标记无歧义）。
- **防误读（词同物异）**：标记字面量里的 `SYSTEM` 意为「**框架自产评论**」，与 `subjectType` 的取值 `SYSTEM`（离线批算 / 外部规则服务）**不是一回事**，二者不得互相引用或替代。字面量本身已冻结不动。

**字段模型**：`DecisionEvidenceVO`，**单一类型 + `outcome` 判别式**（不是分型）—— 读者要用一套字段读三种结局。

**`outcome` 三叶子态**：`SUGGESTION_PRODUCED` / `NO_SUGGESTION_BY_POLICY` / `SUGGESTION_FAILED`。`未产出` 保持**上位词**（仅作文档分类，**不承载契约取值**）—— 上位词不能与自己的下位词并列在同一枚举里。

**字段分组**（2026-09-25 形态定稿，见头部登记 ③）：判别 / 承载（`outcome`、`schemaVersion`、`idempotencyKey`）；建议（`suggestedAction`、`actionSummary`）；证据（`modelId`、`inputSnapshot`、`rawOutput`、`rationaleFacts`、`rationaleNarrative`、直提自述位 `attestedDataSources`）；出处（`provider`、`chainStage`(primary · fallback · rule)、`degraded`(可空 `Boolean`)）；主体（`subjectType`(AI · SYSTEM · USER)、`subjectId`、`subjectName`）；完整度（**按方向分记两套**：`outboundRedacted` / `outboundTruncated` / `outboundCompleteness` 与 `inboundRedacted` / `inboundTruncated` / `inboundCompleteness`）；失败（`failureKind`、`policyReason`）。**时间不进 JSON** —— 由评论行 `TIME_` 列填充，落在**读侧专属字段 `recordedTime`**（`Date`；写侧恒不填、载荷不含该键；读侧投影逐行从 `ACT_HI_COMMENT.TIME_` 填充，故矩阵中该字段四列皆为「读侧专属」而非产出路径格）。**字段集住所**：`DecisionEvidenceVO` 与 `DecisionRationaleFact` 住 core `…core.vo`；`DecisionOutcome` / `DecisionPolicyReason` / `DecisionFailureKind` / `DecisionChainStage` / `DecisionSubjectType` / `DecisionCompleteness` / `DecisionRationaleFactKey` 与证据常量类 `DecisionEvidenceComment` 住 core `…core.enums`。`subjectId` / `subjectName` **可空**（判别式是 `subjectType`，ID 与显示名是描述性字段）。

**③ 标志与 `completeness` 的互锁（机械守卫，写入侧契约）**：每方向 `PARTIAL ⇔ (redacted ∨ truncated)`；`(FULL ∨ NO_PAYLOAD) ⇒ (¬redacted ∧ ¬truncated)`；`NO_PAYLOAD ⇔ 该方向载荷字段为空 ∧ ¬redacted ∧ ¬truncated`；`FULL / PARTIAL ⇒ 该方向载荷字段非空`。故「无实际载荷」由第三值**单一承担** —— 不被布尔兼职，也不被 `FULL` 兼职。该互锁是**写入侧**契约（框架恒填）；读侧因版本错配降级出的 `null` 不触发它。

**④ `failureKind` 的双向守卫**：`SUGGESTION_PRODUCED ⇒ (failureKind == null ∨ failureKind == INBOUND_PROCESSING_FAILED)`；`failureKind == INBOUND_PROCESSING_FAILED ⇒ outcome == SUGGESTION_PRODUCED`；`NO_SUGGESTION_BY_POLICY ⇒ failureKind == null`。`DecisionFailureKind` 的类型 javadoc 须登记该**例外值**（七值中唯一可在产出态出现者）。

**⑤ 必填理由的登记义务**：逐格理由只能引 `outcome` 分支、**产出路径**或 `subjectType`，不得引「因为会调模型」（命名宪章 §2.B.5.2 / §2.B.5.3）。

**⑥ 读侧专属格**：`recordedTime` **不由写入器产出** —— 它是**读侧承载**（值来自评论行 `TIME_`，非提交方），故四列皆记「读侧专属」而非「必填 / 可空」。该格**不参与**「矩阵任何一格都写不出来」的构造期强制（写入器不碰它）；其形态与读侧填充归 §5 读侧硬清单第 7 项的投影实现（2026-09-29 落地，见头部登记）。

**出域控制对本模型的四处修订**（由出域控制决策推回；**2026-09-25 形态定稿**，见头部登记 ⑤）：

① `completeness` 扩为**四值** —— `FULL` / `PARTIAL` / `NO_PAYLOAD`（该方向**本无**载荷）/ `RESTRICTED`（**有**载荷但按政策不可落盘）。**两类入站降级由此先分类型**：**政策性不可落盘** ⇒ `inboundCompleteness = RESTRICTED`（落原因、**不计错误指标**）；**策略执行异常** ⇒ `inboundCompleteness = NO_PAYLOAD` + `failureKind = INBOUND_PROCESSING_FAILED`（**计入错误指标**）。二者在标志层即可区分，不再混用。
② 标志须**按方向分别记录**（出域载荷与入站落盘载荷各记一套），字段形态见上「字段分组」——词根不变，方向限定词 `outbound` / `inbound` 为**允许的标识符形态**。
③ `SUGGESTION_PRODUCED` 下承载**入站加工失败的子失败标记 + 最小化占位**：**取破例取值，不另设字段** —— `failureKind` 在该态**唯一**允许 `INBOUND_PROCESSING_FAILED`（双向守卫见矩阵 ④）。「最小化占位」的形态 = `rawOutput` **置 `null`**（不落任何内容体）：「为什么空」由 `inboundCompleteness = NO_PAYLOAD` + `failureKind` 的组合承担 —— 占位文本要么是假数据（污染审计）、要么是新字面量面，组合表达信息等价。
④ 直提情形的**可选数据源自述位** = `attestedDataSources`（`List<DecisionContextSource>`；元素类型取「节点声明四属性与 BPMN schema」已定的闭集枚举，**成员集由「出域控制的实现形态」登记**—— 本件只登记依赖，不定义成员，**不以 `List<String>` 占位**）。三态可区分：`null` = 位缺失（未申报）/ `[]` = 显式空集（声明未使用）/ 有值 = 申报了具体来源；序列化时 `null` **省略该键**。

**三条分工与权威归属**：

- `suggestedAction`：给**机器**读（同型值比较），**唯一判定权威**；与 `actionSummary` 的自然语言表述冲突时一律以它为准。
- `actionSummary`：给**人**快速扫视，**不得作为判定权威**。
- `rationaleFacts`（类型化）+ `rationaleNarrative`（文本兜底）：给**审计 / 监管**核查逻辑链条。

**⚠️ 一处必须写死的边界**：`suggestedAction` 是结构性事实，但**框架不提供从它到流程推进的任何通路**。应用若自行消费该值去 `completeTask`，那是**应用侧行为，不经框架**。

**主体**：`subject` 进 JSON，AI 作为**独立身份**登记。`addComment` **没有 userId 入参**，其 `USER_ID_` 取决于调用线程的认证上下文（异步拉管线里通常为 null），框架不指定、也不该去设线程级认证用户 —— 所以正确表述不是「不应把主体放 `USER_ID_`」，而是「**不能**」。**`ACT_HI_COMMENT.USER_ID_ ≠ 决策证据的真实产出主体`**；`USER_ID_` 为空反而是好事（通用 UI 的 `author` 为空，不会被误认成某人的意见）。

**挂载层级（2026-09-25 改述，见头部登记 ⑥）**：证据挂**该 `taskId` 所属的那条记录** —— **非会签节点**（读侧无子记录，`buildNormalRecord` 直接产出父 VO）⇒ 挂 `ApprovalRecordVO.decisionEvidences`；**会签节点** ⇒ 挂对应的 `CountersignSubRecord.decisionEvidences`，此时**父 VO 的该字段恒空**。同一条证据**不重复挂两层**。读侧「证据行数 ≠ 决策次数」的说明须写在**证据实际所在的层级**。（原句「证据一律挂 `CountersignSubRecord`」按字面在非会签节点上无子记录可挂，与既有读侧事实不符。）

**读侧容错条款（2026-09-25 显式化，见头部登记 ⑦）**：证据行**判别式不可解析**（`outcome` 未知）或**载荷损坏**（有标记但 JSON 不可解析）时，处置**只限于**「**跳过该条有效证据投影**」—— 该条证据不出现在 `decisionEvidences` 中，同时记一条可观测信号。**审批轨迹行本身不得因此消失**：`action` / `comment` / `operationComment(s)` / `actorId` / 时序一律按既有读侧规则照常产出。**次要枚举**（`policyReason` / `failureKind` / `chainStage` / `subjectType` / `completeness`）取值未知时**不做整条跳过**，只做**字段级降级为 `null`**，该条证据仍投影。**`schemaVersion` 高于本读侧已知最大值**时**尽力读、不做版本门禁**（与 fail-soft 一致：审计面最怕读不出来）。

**锚点：`taskId` 是结构性必备** —— 由「证据必须配建议动作」+「建议动作必须匹配当前任务可用投票动作」推出：一条合法准入的提交**必然存在当前任务**。**推论**：v1 **不支持无任务锚点的证据**（属 P1 证据生成器，v1 不单独进该位点）。另需说明：`ACT_HI_COMMENT` **没有节点列**，节点级锚定本就无法从行内容推断。

**写入可行性（物理限制）**：`addComment` 强校验**运行时**执行树，**实例结束后直接抛 `FlowableObjectNotFoundException`**。故：① 承认边界 —— 晚到证据降级为**系统日志 + 可观测性指标**，不再作为审批轨迹的一等成员；② **死守不绕过引擎 API** —— **否决**经 `CommentEntityManager` 直插 `ACT_HI_COMMENT`（破坏事件派发 / 审计语义 / 事务与并发控制，且随版本升级成为定时炸弹）；③ 把「晚到」从常态压成边缘（超时上限绑定实例存活期）；④ 登记为幂等身份预留槽位中的一种标准失败后果。

**只读承诺（框架契约层面）**：写入面只允许生产侧写入（**不提供**任何 update / delete / 撤回证据的 API）；读取面 `getApprovalHistory` 是**唯一**读入口；生命周期面随流程实例历史删除而删除。**⚠️ 必须写清**：「只读」是**框架契约只读，不是数据库物理不可改** —— 引擎层有现成的改 / 删 API（`saveComment` / `deleteComment` / `deleteComments`），数据库层也无任何约束。这三个 API 须作为**「已知不设防面」**列出，否则审计方会以为这承诺比实际更强。

**生命周期代价**：删历史实例**级联删**该实例全部评论 ⇒ 证据随实例消失。**当前不承诺比实例活得久**。

**一处有意分歧（必须记明）**：本 ADR 早期草案与 `CONTEXT.md` 原文曾写建议通道「也不出现在审批轨迹里」。本决策**修正**之：建议通道**不改变流程推进**，但其「建议提交」**以只读决策证据组形态进入审批轨迹**。

来源：探索期决议（审计证据模型与落点）。

### 6. 出域控制：两道位点 + 一个具名策略

**总纲**：**装配器**做**数据源级**结构性最小化（框架强制、fail-closed），**出域策略**做**内容级**加工（应用实现、按 key 引用）；框架只承诺「实际出域载荷」这一事实、安全默认、以及**策略之后不再注入业务数据**。

对「调用前的内容加工 / 调用参数装配 / 仅契约由应用实现」的正面回答：**前两者都要，排除第三者** —— 只做契约约定，会让框架对「到底哪些数据出了域」不承担任何可验证承诺，正撞 kill switch 1 条件③。

| 位点 | 所在步 | 职责 | 强制方 |
|---|---|---|---|
| ① 装配器 | 拉管线「装配上下文」 | **有效数据源声明**（数据源级）：只装配声明允许的上下文来源 | 框架（结构性） |
| ② 出域策略 | 「调 provider」前 | **内容选择 + 变形（脱敏 / 摘要）+ 策略级截断** | 应用（具名策略） |

- 框架在 ② 之后加**硬上限 clamp**（最后一道，应用不可放大），作用于**最终实际出域载荷**。
- **框架在策略之后不得注入新的业务数据**，只允许协议 / 格式层构造。
- 策略**只面对 provider-中立的结构化载荷**，不得看到任何 provider 方言；provider 格式化由框架在策略之后做。

**硬上限 clamp 的形态定稿（2026-09-25）**：

- **单位 = 载荷（provider 缝格式化之前的 provider-中立形态）序列化后的 UTF-8 字节数**；**硬上限 = 32 KiB**（框架常量，**v1 无应用侧调参口** —— 本节只要求「不可放大」，**未**要求「可调」）。
- **收缩语义 = 整段丢弃 + 兜底拒绝**：按 `dropPriority`（数值越大越先丢）**整段**丢弃至满足上限；**丢到全空仍超**（单段自身超限）⇒ **拒绝出域**（硬闸 ⇒ `SUGGESTION_FAILED` / `INTERNAL_ERROR`）。**段内永不动刀** —— 段内截断会造出「**看起来真实、实则残缺**」的值而**污染审计**（与第 5 节否掉占位文本同一条理由）。
- **物理前提已核**：`ACT_HI_COMMENT.FULL_MSG_` 为 **BLOB**（建表语句一手核实）⇒ **列本身不设上限**；32 KiB 是**设计选择**（成本 / 上下文窗口），不是存储硬约束。
- **入站方向同一上限、同样不截断**：超限 ⇒ `rawOutput = null` + `inboundCompleteness = NO_PAYLOAD` + `failureKind = INBOUND_PROCESSING_FAILED`。**如实登记**：该复用把「策略抛异常」与「clamp 超限」压成**同一可观察值**（七值闭集禁止新增取值是本机制不能破的约束）。**（2026-09-26 补）** 该压合在**观测面同样不可分** —— 结构化日志 / 指标 / 观测回调三者**都不区分**两者，**不得据此判因**；本机制不为此另加 `detail` 之类维度（那等于变相新增取值）。
- **clamp 的效果计入 `truncated`**；与装配器丢弃的分界见「标志与证据接缝」。

**主体（谁决定）**：应用决定「策略怎么做」（App 级实现类，具名多策略、每策略唯一 key、可多节点复用）；建模者 / 节点决定「用不用、用哪个」（节点声明：启用 + 有效数据源声明 + **单个**策略 key，**严格单策略引用**）；框架决定「没说时怎么办」（安全默认）。数据源集 = **v1 固定枚举**，不做可扩展 SPI。

**默认与安全（fail-closed 分层）**：未声明节点 ⇒ 不触发、不出域、**不记为失败**；**零 token（未声明任何数据源）** ⇒ 空装配 ⇒ **短路、不调 provider** ⇒ **按政策未产出**（`NO_SOURCE_DECLARED`）；允许应用**显式**定义应用级默认数据源集，**禁止框架隐式全集默认**。

**「有效数据源声明」的构成（2026-09-25 形态定稿）**：`有效数据源集 = 节点级 token 集（缺席时下取）› 应用级默认集 › ∅` —— **严格 fallback 链**。**缺席**（属性不存在）⇒ 取应用级默认；**显式空集**（`decisionDataSources=""`）⇒ **恒** `NO_SOURCE_DECLARED`、**不取**默认（**显式否决**）。三态与 `attestedDataSources` **同构**：位缺失 / 显式空集 / 有值。**应用级默认集的形态 = 定型 Bean**（与决策目标 / 出域策略同族；不用扁平配置属性 —— 数据源声明是**安全边界**）。**断点**：`decisionDataSources` **只被装配器读一次** —— 管线只读 `decisionEnabled`（**控制流**），装配器读数据源声明并组装（**数据流**）；**零 token 的判定在装配器内**，产「**空装配**」这一**显式事实**，管线据此短路（**不调策略、不调 provider**）。「空装配」**不得**由「四段全 `null`」反推。

**`DecisionContextSource`（本节词汇，2026-09-25 形态定稿）**：**闭集枚举，住所 = core**（由第 5 节 `DecisionEvidenceVO.attestedDataSources` 结构性逼出，非本节选择）。

- **成员 = 承载单元级**：`PROCESS_VARIABLES` / `TASK_VARIABLES` / `TASK_METADATA` / `PROCESS_INSTANCE_METADATA`。**不在可枚举的元数据上开字段级枚举** —— `businessKey` 与发起人同属流程实例元数据，字段取舍归**策略的内容选择**（与变量不能逐字段声明同理）；「声明了什么段 ⇒ 出去什么段」由此端到端可对。
- **成员各带 `dropPriority`**（`int`；**数值越大越先丢**；**留 10 间隔**、**互异且非空**）—— 顺序是**显式契约**，**不依赖物理声明序**（防 IDE 重排引线上雪崩）。消费者只有出域 clamp。
- **BPMN token = 枚举常量名原文**（大写下划线、大小写敏感、仅两侧空白容忍）—— **不引入映射表**，保持单一真值来源；匿名 token 由第 11 节的部署期阻断兜住，抄错**在部署当场即炸**、不会静默出域。

**出域策略契约**：单一扩展点（内部阶段「选择 → 变形 → 截断」，不暴露独立子 SPI）；**双向非对称** —— 出域方向 = 硬闸（不放行 = 调用不发生），入站方向 = 落盘前加工（可选，默认透传）；**确定性 / 纯**（同一装配载荷 ⇒ 同一出域载荷 + 同一加工记录）；**不得自身发起出域调用**（本地纯计算）；**必须线程安全**。入站方向：政策性不可落盘 ⇒ `rawOutput` 置空 + 记原因（**不计调用失败**）；策略执行异常 ⇒ **不得回退原始响应落盘**，落**最小化占位 / 元数据**，记录为**入站加工失败**并**计入错误指标**。

**出域策略契约的形态定稿（2026-09-25）**：

- **载荷同型**：装配器产出、策略输入与输出、clamp 输入与输出、`inputSnapshot` 的**语义所指**（**非字段类型** —— `DecisionEvidenceVO.inputSnapshot` 的字段类型取 `String`（载荷序列化形态，与 `rawOutput` 同构），理由见头部「收口」显式化登记）—— **同一个类型** `DecisionPayload`（分段定型外壳：`processVariables` / `taskVariables` / `taskMetadata` / `processInstanceMetadata`）。**未声明的段取 `null`（缺席），已声明但该来源为空取空集合** —— 三态让策略无需猜测。**变量段的内容天然未定型**（应用自定义命名空间，引擎无从定型），**契约面仍是定型的**（段是具名、定型的外壳字段）；不为变量段再包一层无意义的类型壳。
- **单一接口、双向两方法**：`DecisionPolicy`（**不带方向词** —— 词条明文「双向服务」）；`applyOutbound(DecisionPayload) → DecisionOutboundResult`、`applyInbound(String) → DecisionInboundResult`（入参形态 = 已冻结的 `rawOutput`，**裸 `String`**，不套壳）。
- **「说不」住在显式结果位，不住 `null`**：`DecisionOutboundResult{ permitted, payload, record }`、`DecisionInboundResult{ persistable, rawOutput, record }`。**要求**：`permitted / persistable` 为 `true` 时对应内容位**必非空**（守卫归面 6）。**主动拒绝 = 合规、不计错误**（出域 `permitted=false` ⇒ `POLICY_REJECTED`；入站 `persistable=false` ⇒ `RESTRICTED`）；**抛异常 = 系统故障、计错误**（出域 ⇒ `INTERNAL_ERROR`；入站 ⇒ `INBOUND_PROCESSING_FAILED`）。二者**严禁混用**。
- **加工记录 `DecisionProcessingRecord{ redacted, truncated }` 只承加工事实**，**不承「说不」** —— 与结果位的边界是**结构保证**（也避免让一个字面恒真的字段兼职，撞第 5 节「`NO_PAYLOAD` 不被布尔兼职」的同一把尺子）。
- **不给策略传节点身份**：`decisionPolicy` 这个 key 本身就是建模期的声明；要按节点分流就注册不同策略。**策略是纯函数**，路由逻辑不污染其内部。
- **策略与决策目标同型**（bean + 唯一 `key()` + 节点按 key 引用 + 部署期校验）—— 本节不引入新形态。

**策略引用的三档防御**：

| 档 | 时点 | 作用 | 后果 |
|---|---|---|---|
| 主闸 | **部署期**（注入 `ProcessValidator`，extension-only、**零 core 改动**） | 校验引用的策略 key 是否存在 | 非 warning 错误 ⇒ 抛异常 ⇒ 事务回滚、部署失败 |
| 复核 | 启动期 / 部署后 | 全量复核；**不承诺阻止已提交的部署**（引擎无「容器就绪且部署前」钩子） | 不一致 ⇒ fail-fast 应用启动 |
| 最后防御 | 运行期 | 该时刻声明与注册表不自洽 ⇒ **阻断式**不出域 | 归 `SUGGESTION_FAILED`，计错误指标，**必须可观察** |

**标志与证据接缝**：标志（`redacted` / `truncated` / `completeness`）由**框架从「加工记录 + 自身 clamp」推导**，**策略不自填**（诚实性上限 = 框架只保证「不接受策略直接给标志」）；`redacted` 含脱敏与摘要、**不含截断**（截断由 `truncated` 单列）；**无任何加工 = `FULL`，发生任一加工 = `PARTIAL`，无实际载荷 = 第三值**；**`inputSnapshot` = 加工后、clamp 后的最终实际出域载荷**（即「模型实际看到的」），`rawOutput` = 入站加工后版本；装配器丢弃的来源**不计入任何标志**，另记**可观测计数**；标志**按方向分别记录**（出域 / 入站各一套）。

**标志推导的形态定稿（2026-09-25）**：**推导输入 = 两个显式事实**（由管线供给），**不是**对九种 `policyReason` / `failureKind` 的**路径枚举** —— `hasOutboundPayload`（装配器产出非空载荷 ∧ 策略放行）、`hasInboundPayload`（入站有内容且策略判可落盘）。**状态驱动，不路径驱动**；「某条路径下到底有没有载荷」是**面 4** 的知识，本节不替它枚举。

| 方向 | 推导 |
|---|---|
| 出域 | ¬`hasOutboundPayload` ⇒ `NO_PAYLOAD`；否则 无加工 ⇒ `FULL` / 有任一加工 ⇒ `PARTIAL`。`outboundRedacted` = 记录 `redacted`；`outboundTruncated` = 记录 `truncated` ∨ **clamp 丢段** |
| 入站 | 同构；另 `RESTRICTED` = 有内容但 `persistable = false` |

**按方向的取值域（必须显式写下，否则「按方向分记」会被误读成「四值两边都可达」）**：`outboundCompleteness` ∈ {`FULL`, `PARTIAL`, `NO_PAYLOAD`}（**三值**）；`inboundCompleteness` ∈ 四值。**出域方向不取 `RESTRICTED`** —— `inputSnapshot` 是「**离开本域的到底是什么**」的**唯一证据**，允许策略屏蔽它等于给 **I2「无未留痕出域」开后门**。这**不违反**「每取值须有可达构造点」：该纪律的对象是**类型的取值集**，而 `RESTRICTED` 的构造点在**入站**。

**直提列（第 3 节派生 3 的形态落地）**：出域方向**恒** `NO_PAYLOAD`；`outboundRedacted` / `outboundTruncated` 取 **`false`**（**诚实的真空真** —— 无载荷即无加工；`NO_PAYLOAD` 由 `completeness` 独立承担，不违「不被布尔兼职」）。入站方向按提交方是否交载荷取 `FULL` / `PARTIAL` / `NO_PAYLOAD`（**取不到 `RESTRICTED`** —— 直提的入站加工**不经策略**，见下）。

**直提的位点适用面（2026-09-25 形态定稿）**：直提**不经出域策略** —— `decisionPolicy` 属节点声明，而推面与声明解耦（第 3 节），**key 无从取得**。框架只施加与拉面入站**同构的兜底**（硬上限 clamp）；「异常不得回退原文」在直提下**无可回退之物**（提交方没交就是没交）。**入站载荷的内容卫生 = 提交方自律**，与「数据源声明退化为自律」**同一条逻辑**：**框架无从核查 ⇒ 退化为自律**。

**装配器丢弃 vs clamp 丢弃（对偶，勿混）**：**装配器丢的来源不计任何标志**（它是**声明面最小化的基线**，不是「加工」，另记**可观测计数**）；**clamp 丢的计 `truncated`**（它是「加工」）。

**三档的覆盖关系（漏网 → 档位，2026-09-25 补）**：三档不是三句并列口号，而是一条链 —— 三者的**漏网集合**逐条对上：

| 漏网情形 | 承接档位 |
|---|---|
| 新部署（经本引擎） | 主闸（部署期） |
| **存量已部署定义**（扩展装上之前就在库里）× 当前注册表 | 复核（启动期） |
| **注册表漂移**（被引用的策略 Bean 被移除 / 改名） | 复核（启动期） |
| **同集群其他节点部署** / **绕过校验的部署**（`disableBpmnValidation()`） | 最后防御（运行期） |

**三档的形态定稿（2026-09-25）**：

- **主闸 = 叠加式注册，不得整体替换**。一手事实：`setProcessValidator` 是**整体替换**语义（字段非 null 即保留），而引擎装配期会自动装 26 个内置 `Validator` ⇒ **直接替换会静默摧毁全部内置语义校验**。契约钉为：**自建默认实例**（`ProcessValidatorFactory#createDefaultProcessValidator`）**+ `addValidatorSet(new ValidatorSet(…))` 再 `setProcessValidator(...)`**。**引擎级装配（`ProcessEngineConfigurationConfigurer` / `ProcessEngineConfigurationConfigurer` 路径）归面 7**。
- **复核的触发形态 = `SmartInitializingSingleton#afterSingletonsInstantiated`**（上下文 refresh 之内、Bean 齐备之后）⇒ 不一致时**刷新失败、应用不启动**。用 `ApplicationRunner` / `ApplicationReadyEvent` 会**先起后炸**，留下半启动上下文。**复核对象 = 全部已部署定义（含存量）× 当前注册表**；判定式**沿用第 11 节的「唯一显式例外」**（出现本机制扩展属性 ∧ 不满足规则）⇒ **未声明的遗留定义不被误伤**。
- **复核的连带后果（如实披露，运维须知）**：**移除一个仍被引用的策略 Bean ⇒ 应用起不来**。这是本节「不一致 ⇒ fail-fast 应用启动」的**必然结果**，也是第 12 节「validator 始终生效」在启动期的对应物；但它确实把「拔掉一个 Bean」从**运行期故障**升级为**启动期故障**。
- **最后防御的 `failureKind` = `INTERNAL_ERROR`**（第 5 节已冻结七值闭集，**不新增取值**）；**阻断式**（出站调用不发生 ⇒ 符合 I2），计错误指标，**必须可观察**。

**core 改动账本（本节，2026-09-25 改述）**：**机制实现（装配器 / 策略 / clamp / validator）零 core 改动**；其**词汇** `DecisionContextSource` 的 core 住所是第 5 节**读侧承载**（`attestedDataSources` 元素类型）的**既有账**，本节**+1 字段**（`dropPriority`）。**如实记账**：core 侧不是「零改动」，而是「**+1 字段**」。**第 11 节的四行残留账本不受影响** —— 那四行统计的是对**既有** core 的修改。

来源：探索期决议（数据边界钩子层级）。

### 7. 凭据与配置边界

**总纲**：**「框架不托管真实凭据」= 框架不声明、不持久化、不记录、不解释凭据内容**；凭据仅由应用在调用点提供、经框架无状态透传。

**出站调用链 = 两层缝**：

```
装配器 → 出域策略 → 框架 clamp → Provider 缝（协议/方言格式化 + 凭据附着 + 响应解析）→ Transport 缝（纯网络 I/O）→ 入站加工
```

- **Provider 缝**（协议 / 方言层）：默认 = Apache HttpClient + Jackson；**换厂商 SDK = 换这一层**（换实现不动契约）。
- **Transport 缝**（纯网络 I/O 层）：**公开 SPI**，供无网测试 / 特殊网络栈替换。
- **替换代价（写进契约）**：应用替换 Provider 缝后，框架只保留超时 / 总预算 / 幂等键复用 / 可观测；**HTTP 语义的 `failureKind` 随之失效**（退化为应用自报或 `INTERNAL_ERROR`），**同时失去框架侧凭据位点**。

**凭据位点（只服务默认 Provider）**：**单一 bean + `decisionTarget` key 路由**（凭据是同一类解析逻辑按目标取值，不是多个领域单元）；**框架每次调用前实时解析，绝不缓存**；**缺失 = 合法**（应用未提供解析器即视为不需认证材料，由远端 401/403 兜底）；**防泄漏 = 类型系统性质，不是纪律** —— 解析 SPI 返回**不透明值类型**（锁死 `toString()`、**无任何状态提取方法**、不实现序列化契约），框架只把它作为请求装饰载体原样转交（**纪律不可核查，类型可以**）；`OUTBOUND_CREDENTIAL_INVALID` **只由 Transport 返回的 401/403 产生**，解析侧失败**折叠进同一枚举**（不新增枚举）；框架**不读 Spring `Environment`**、**不定义任何承载凭据的属性**。

**屏蔽清单（五出口，入 ADR + 守卫测试）**：凭据不得出现在 ① 证据载荷 ② 结构化日志 ③ 异常 message 与堆栈 ④ 可观测信号的维度与 tag ⑤ ADR / 文档 / 示例。**结构保证**：凭据附着发生在装配之后，**凭据从不是载荷的一部分**。

**节点声明 schema**：载体沿主仓「按节点声明」惯例（BPMN 扩展属性 + SPI 按节点解析），但**开独立命名空间**（不塞进 `flowable:` 引擎保留命名空间）：

| 属性 | 语义 | 取值 |
|---|---|---|
| `decisionEnabled` | 启用开关 | **只认小写字面量 `true` / `false`** |
| `decisionDataSources` | **业务数据上下文来源枚举**（有效数据源声明） | 逗号分隔、大小写敏感、空白容忍 |
| `decisionTarget` | **外部物理调用源**的 bean key | 单值 |
| `decisionPolicy` | **出域策略**的 bean key | 单值 |

**四态**（拉面）：未声明 / 显式禁用 ⇒ 不触发、无记录、非失败；启用但无有效数据源 ⇒ **按政策未产出**（`NO_SOURCE_DECLARED`）；声明齐全 ⇒ 触发。

**严格校验（全部部署期 fail-fast，由 `ProcessValidator` 主闸承担）**：取值非 `true` / `false` 字面量 ⇒ 阻断；**写了其他决策属性却没有 `decisionEnabled`** ⇒ **阻断**（**绝不允许静默降级成「未声明」** —— 那是最危险的失败模式：建模者以为配好了）；未知数据源枚举值 ⇒ 阻断；`decisionTarget` / `decisionPolicy` 指向不存在的 key ⇒ 阻断；`decisionEnabled=true` 时 **`decisionTarget` 必填**，**绝不提供全局默认 target 回退**。

**决策目标 ≠ 决策源（拒绝合并）**：

- **决策源**：一次决策在**语义上的出处** —— 「谁做出了这个决定」。以**出处标识**进证据、以**维度**进可观测信号。**不承诺可被调用**。
- **决策目标**：框架配置面上**可被框架发起调用**的接线单元 —— 应用声明的一个 Spring bean（携唯一 `key()`，接入信息内聚在 bean 内部）；节点以 `decisionTarget` 引用，部署期校验存在。它是**执行对象**。
- **分界线 = 可调用性**。**v1 允许一一对应，但永不合并** —— 通用化决议问的正是「未来是否出现**没有决策目标的决策源**」，合并即让该问题无法表述。
- 决策目标与出域策略**同型**（bean + 唯一 `key()` + 节点按 key 引用 + 部署期校验），**不引入主仓没有的嵌套 `@ConfigurationProperties` 模式**。

**全局默认面与 fail-closed**：承载 = `@ConfigurationProperties`（`flowable.plus.decision.*`），**全部扁平非机密值**（全局启用开关**默认关**、应用级默认数据源集、超时上限、尝试次数上限、执行器大小、退避默认）；**默认数据源集缺失或为空 = 空集**，框架代码中**不得存在任何隐式全集兜底**（守卫测试钉死）；全局数值上限**只能调低、不可放大**。

**策略注册与契约性质**：策略接口 public（消费者 = 应用）；注册表 **internal**（消费者 = 框架自身，守 ADR-0030）；注册 = Spring bean 自动收集，**重复 key ⇒ 启动期 fail-fast**；契约性质 = 确定性 / 纯 + **必须线程安全**（有界线程池会并发共用同一策略 bean，框架不做每调用实例化）。

**可测性与 CI**：**验收句 = 无外网、无真实凭据，在 Docker 内 Testcontainers 三库（H2 / MySQL 8 / PostgreSQL 14）下 `mvn clean verify` 全绿**。**stub 是契约，recorded 不是** —— 默认 Provider 必须暴露可注入的 Transport 缝供测试回放固定 fixture；**recorded 录放不进 v1**（录制需要真实 key，恰是本机制要避免的 CI 前提），只能作为离线生成 fixture 的可选手段，不进公开 API。**测试分层** = extension 纯逻辑单测（不依赖 Spring / DB）+ starter 端到端集成测；**不发布 test-jar**。**CI 矩阵零改动**（ADR-0014 不需修改）。

来源：探索期决议（凭据与配置边界）。

### 8. 失败后果：降级 + 建议通道留痕

**决议**：新机制的失败后果 = **降级 + 建议通道留痕；默认不触流程状态。框架只承诺失败「发生」这个事实，不替接入方选失败「之后」怎么办。** 一句话：**失败要响，但响在建议通道里，不默认响在流程状态里。**

对「fail-fast / 跳过自动提交 / 转人工 / 组合」的正面回答：新机制**不沿用** fail-fast；「跳过自动提交」不是后果选项而是**结构性事实**；「转人工」**不是真实选项**（P3 里人始终在环，助手失败 = 退回「人手上有一个没有建议的任务」= 栈的原状）；实际形态是「降级 + 可观察」，升级由应用在可观察之上自建。

1. **作用域**：本 ADR 只定**新机制**的失败语义；`AutoApprovalRule` 的 fail-fast 与整流程回滚**原样不动**。**新旧失败语义的分歧是有意的，必须写进 ADR** —— 否则读代码的人会以为漏了。
2. **默认后果轴 = 降级 + 建议通道留痕**：失败不写流程状态；失败作为**建议通道的一等记录**落下，与建议同通道、同读者。承重对象是**审阅建议的那个人**，不是流程。
3. **只承诺可观察，不提供分派**：「失败即走严路径」这类后果策略**不提供**，由应用在可观察之上自建。缺口在事实、不在策略。
4. **位点服务的准入失败 = 同步抛异常；失败的物质化由位点服务自身、在抛出之前完成**。语义「本次提交没有发生」是**提交层面**的语义，**不等于审计面上无痕**。**（2026-09-26 订正，见头部登记）** 原句「拉管线是唯一负责把失败物质化为一等记录的地方」**作废** —— 该句立法时**直提尚不存在**，而直提**无拉管线**（第 3 节派生 4 自其引入起就要求直提准入失败必须物质化）。订正后四点：**(i) 物质化宿主 = 位点服务自身**（写侧仍走 extension 内部写入器、**不进公开 API**）；拉管线在准入失败上**只接住、不再重复落行**，其物质化职责**收窄为拉取期失败**（超时 / 非 2xx / 响应不可解析 / 凭据失效 / 入站加工失败 —— 那些情形位点服务**从未被调用**）。**(ii) 落行判据 = 该次提交是否带齐三项前置**（`taskId` ∧ `idempotencyKey` ∧ `subjectType` 皆非空）—— **状态驱动**，**不是**对拒绝原因枚举的路径驱动（承诺与否不取决于「第几条规则先失败」）；带齐 ⇒ 落 `SUGGESTION_FAILED` + `failureKind = SITE_ADMISSION_REJECTED` **再抛**，缺任一 ⇒ 不落行、退**日志 + 指标**（三项逐条理由见第 9 节第 9 条）。**(iii)「位点服务自身不落记录」的适用面限定为「公开 API 不暴露失败写入面」** —— 其立法意图（探索期决议「位点服务与建议提交模型签名」）是堵死**应用**自造失败行污染审计面与错误指标，**不是**禁止框架自身落行。**(iv) 推论：第 3 节派生 2 的双射在失败行上依然成立** —— 直提失败行的出处组**全 null**；拉面失败行**在确已发起主链路出站调用时**必带 `provider`（拉面准入失败发生在 Provider 缝之后），而**从未出站**的失败（装配失败 / 策略拒绝 / clamp 拒绝 / 目标不可解析 / 未归口兜底）整组为 null —— 出处组与 `modelId` / token 同为「确已出站」的外部痕迹，不制造未发生调用的记录（**2026-10-02 由主仓 #104 收敛：与第 10 节观测面同一判据，原「拉面失败行必带 `provider`」的泛化读法随之收窄**）。
5. **三态可区分，共享同一后果**（都落一等记录、都不进流程状态、都不静默），差别只在分类与观测后果。
6. **「显式」的下限 = 结构化日志 + 指标**：失败记录自身写不下去时退到更外层的可见面，三条底线不变：**不致命、不动流程状态、不静默**。
7. **作用域收窄**：三态与后果归本决策；护栏决议定检出 / 重试 / 超时 / 熔断 / 禁用 / 指标 / 成本，可细化类别与严重度，**不得重新定义顶层三态**；失败记录的字段与落点归证据模型决议；重试 / 回放导致的重复失败记录归幂等决议。

**负空间自查**：不允许静默通过 —— 每一个「到点但没产出」的情形都必须落成**可区分的顶层状态**；仅**三类**情形不落记录 ——「什么都没发生」（未声明 / 未触发，这是关闭状态）、「**未带齐三项前置的准入失败**」（缺 `taskId` / `idempotencyKey` / `subjectType`，由同步异常响给调用者并退日志 + 指标）与**结构性写入失败**（锚点失效 / 实例已结束，语义以第 9 节第 10 条为准）。三者都不是静默。**（2026-09-26 显式化，见头部登记）** 原句「仅两类」的**计数与展开均已过时**：其一，「提交没发生」**只是提交层面的语义** —— 三项前置带齐的准入失败是**落记录**的，「不落记录」只及于前置不足的那一部分；其二，原句漏了第 9 节第 10 条已确立的第三类。不允许无证据自动提交 —— 新机制无自动提交通路，**结构性成立**。

来源：探索期决议（失败后果策略）。

### 9. 幂等与回放

**决议**：框架承诺**幂等身份** —— 一次「建议提交」在**同一锚点内**被重复到达时，可被第三方稳定判别；框架**不抑制**重复，而是**如实留痕并标出**。

三问的正面回答：① 决策**可以**重放；② 重放会产生**重复证据行**，但**不会**产生流程的二次推进（推契约无通往流程推进的通路）；③ 原假设的「双重守卫 + 乐观锁」**不作用于新机制**。

**前提更正（一手核实）**：`isFirstStart` 只是 javadoc 里的概念名（实际是「该实例已完成历史任务数 > 0 即 return」的即时查询）；「首任务快照隔离」读的是**运行时**活跃任务而非历史快照；引擎乐观锁 `REV_` 仅在 `ACT_RU_TASK` / `ACT_RU_EXECUTION` —— **`ACT_HI_COMMENT` 无 `REV_`**。**结论：这三道保护对新机制零覆盖**；它们保护的是**老路径的流程状态写入**。另核实：老路径 `startProcess` 若被重复调用，**每次生成新实例**，守卫不拦。

**定案**：

1. **范围**：只解新机制下的重复证据行。老路径 `startProcess` 重启产生的**重复实例**（自动审批重跑）**out of scope**（属主仓既有 GA 行为，是通用「重复发起」问题）。
2. **幂等是框架缺口**：框架是决策证据**唯一的写入者与唯一的读取者**；区分「一次决策被重放」与「两次独立决策」所需的信息只在写入点可得。
3. **幂等身份 = 调用方提供**（推契约的**必填**字段）；拉管线侧由框架按**确定性规则**推导。框架无法从内容推导 —— 同一锚点上两次内容相同的 `AGREE` 既可能是重放、也可能真是两次独立决策。
4. **身份须决策源中立**（不绑 AI，理由同 `DECISION_EVIDENCE` 命名）。
5. **判别作用域 = 锚点内**；跨锚点同键**不承诺**。
6. **拉管线侧的键由框架确定性推导**（如 `锚点 + 触发事件标识`），**不得**用随机值 / 时间戳。由此三种情形各归其位：管线自动重试 = **同键** → 重放；网络补发 / 幂等重发 = **同键** → 重放；人工触发重建 / 补算 = **新触发 = 新键** → 二次决策。**（2026-09-25 显式化）** v1 的拉面键 = **一元锚点 `taskId`**（框架自造、**不透明串**，其形态**不构成契约面**）；「人工触发重建 / 补算」的**新键由推面提交方提供**（调用方给一个新的 `idempotencyKey`）—— 本条结论未动，只补「键由谁给」。详见头部登记 ②。
7. **重复到达 = 标注，不抑制**：照记一行；读侧在**同一锚点内**按键分组，**最早 = 原**，其余标为「重放」并指向原行。理由：抑制会丢掉「曾被重放」这个运维信号；标注无并发竞态，不重引会签加签查重记下的已知限制形态。**（2026-09-25 显式化）** 判序 = 锚点内按 `TIME_` **升序**（引擎 `getProcessInstanceComments` 返回的是**降序**、且**无次级排序键**，读侧必须自行重排）；**同毫秒**并列按 `Long.parseLong(ID_)` **数值升序**（默认 `DbIdGenerator` 下块起始严格递增 ⇒ `ID_` 数值序 = 写入序，已源码核实）。**同毫秒本无客观先后**，故该 tie-break 是一条**确定性约定**，不是对真实先后的断言。`ID_` 不可解析（应用替换了 `IdGenerator`）⇒ 该锚点**整体不判**原 / 重放（**拒绝标注**）+ 落日志与指标。详见头部登记 ③。
8. **重放不成为第四叶子态**：三叶子态不动；重放是 `SUGGESTION_PRODUCED` 上的**派生标注**。**派生放在框架读侧**（不由读者各自计算），否则它就不再是框架承诺的值。
9. **缺身份 = 准入失败**：身份 `null` / 空 ⇒ 位点服务同步抛。**（2026-09-26 显式化，见头部登记）** 原句「不落记录（与准入失败同型）」与「调用者是拉管线时由管线物质化」**均订正** —— 准入失败**并不一律**不落行（**三项前置带齐者落行**，见第 8 节第 4 条），且拉管线**不再**承担准入失败的物质化。**落行判据 = 三项前置（`taskId` ∧ `idempotencyKey` ∧ `subjectType` 皆非空）**，三项**各自成因、逐条附理由、不合并、不造上位词**：① `taskId` = **锚点** —— 缺失时证据无处可挂（与「锚点失效 / 实例已结束」**同族不同源**：那两种是**提交已发生、写入期落不下**，本条是**提交未发生**）；② `idempotencyKey` = **可判别性**（本条**原判，理由不变**，见下）；③ `subjectType` = **判别式**，而第 5 节矩阵 D 列要求该字段**必填** —— 缺它写不出一条合法的失败行，**不得用占位值硬凑**（同第 3 节派生 1「模型标识不得硬凑」）。缺任一 ⇒ 同步抛 + **日志 + 指标**、不落行。**缺身份降级为日志 + 指标的理由（原判不动）**：失败记录要与证据共享同一条「可判别」承诺，无身份时**无从判别**，落记录会把同一个第三方的反复重试变成无法归并的审计噪声。**（2026-09-25 显式化）** 「空」的判据 = `null` 或**去空白后为空串**；身份值**原样存、原样比**，**不做任何规范化**（规范化会把不同键并成一次决策，违第 11 条）。**（2026-09-26 订正）** 原句「『由管线物质化』一句在 v1 为空支」**作废** —— 该句已随物质化宿主订正一并移除；「缺身份」在拉面**结构性不可达**这一**事实未变**，若实现期发现该通路可达，按**具名异常**补并登记。详见头部登记 ④。
10. **两个写入失败槽位收窄**（**任务已消失 / 锚点失效**、**实例已结束**）：皆降级为**日志 + 指标**，**不放宽读侧**。
11. **与人工覆盖的分界**：键**相同** = 重放（本决策）；键**不同**但锚点相同 = **二次决策**（覆盖语义域）；键相同锚点不同 = 不构成重放，两条独立证据。

**已知弱点**：① **任务已消失时「未产出」在审批轨迹上不可见**，与 kill switch 1 条件⑤ 在**这一种情形**上相冲（v1 明确收窄，不藏）；② 跨锚点同键不承诺；③ 读侧标注依赖「最早一行」判定，**同毫秒并列**的确定性 tie-break **已定**（第 7 条：`TIME_` 升序 → 同毫秒数值 `ID_` 升序；`ID_` 不可解析则整锚点不判）—— **残余边界**：该兜底依赖引擎默认 `DbIdGenerator`，应用替换 `IdGenerator` 即退化为「不可判」（见「不做 / 已知边界」表）；④ **证据行数 ≠ 决策次数**（须写进 `getApprovalHistory` 的字段说明）。

来源：探索期决议（幂等与回放）。

### 10. 运行护栏与可观测性

**总纲**：本机制 = **框架提供硬保护 + 激活开关 + 可观测信号契约**；**策略归应用**。一切护栏**默认不触流程状态**。

**护栏归属**：**超时** = 框架（每次尝试**一组**出站超时（连接 / 读取）；**全局可配**（`flowable.plus.decision.*`），硬上限**不可放大**。**（2026-09-25 显式化）** 原句「节点可配」在节点声明**四属性冻结**（第 7 节 + 第 11 节）后**无承载物**，故改述为全局可配；若日后要节点级颗粒度，须先解四属性冻结）；**重试** = 框架提供机制、应用给参数（框架**强制**确定性键复用；次数 / 退避受硬上限约束）；**熔断** = **应用**（框架不自带熔断器，只给计数信号 + 暂停位）；**禁用** = 框架（部署期开关，全局 + 节点级，默认关）；**并发** = 框架（有界线程池即唯一并发上限，不另造队列 / 丢弃语义；**（2026-09-25 显式化）** 该池 = **本机制专属**，不复用事件执行器 —— 后者的 `CallerRunsPolicy` 会使事件回调可能在**流程事务内**执行，撞第 2 节定案 8「事务外」）。

**运行预算**：**超时只覆盖出站网络调用**（装配 / 入站加工 / 位点提交是本地步骤，框架不加超时）；**整次决策总预算**含全部重试，**绑定实例存活期**，超预算即放弃整次决策、`failureKind` 取**最后一次尝试**的值（**不新增顶层结局，也不新增枚举**）；**重试是同步的**、在同一次管线执行内完成（框架推导一次键、重试不重新生成），**不引入待重试态**；**可重试集合** = `OUTBOUND_TIMEOUT` / `OUTBOUND_HTTP_ERROR` / `RESPONSE_UNPARSEABLE`；**不可重试** = `OUTBOUND_CREDENTIAL_INVALID` / `SITE_ADMISSION_REJECTED` / `INBOUND_PROCESSING_FAILED`（重试不改变结果，只烧钱）；次数 / 退避 = 框架硬上限（默认 ≤3 次尝试），指数退避 + 抖动，应用可在硬上限内调参。

**资源保护与激活控制**：**池满** ⇒ 落按政策未产出，`policyReason = OVERLOADED`，**不计错误**（过载保护是机制按设计工作）。**（2026-09-25 显式化）** 该结局的**承载面 = 结构化日志 + 独立计数**，**不落证据行** —— 池满意味着**记录任务自身进不去执行器**，正落第 8 节第 6 条「失败记录自身写不下去时退到更外层的可见面」；**本限定不外推**：超时 / 非 2xx / 响应不可解析 / 准入拒绝 / 入站加工失败**各自必须落证据行**。详见头部登记；**禁用**（部署期，默认关）= 机制**未激活** ⇒ **无决策发生 → 不留任何记录**；**暂停**（运行期，**应用持有的进程内内存态**，框架只暴露契约 / setter，不持久化、不带管理端点）= 落按政策未产出，`policyReason = SUSPENDED`，**不计错误**。**铁律**：**禁用 = 无记录**（未激活）；**暂停 = 有记录**（已激活但被暂止）—— 二者不可混，否则「按政策未产出」计数被禁用的噪声污染。

**错误分类（两轴）**：`failureKind`（`OUTBOUND_TIMEOUT` / `OUTBOUND_HTTP_ERROR` / `OUTBOUND_CREDENTIAL_INVALID` / `RESPONSE_UNPARSEABLE` / `INBOUND_PROCESSING_FAILED` / `SITE_ADMISSION_REJECTED` / `INTERNAL_ERROR`）× `severity`（**`ERROR` 进告警** = 凭据失效 / 位点准入拒绝 / 入站加工失败，配置 / 契约问题需人介入；**`WARN` 记录不告警** = 单次超时 / 5xx / 非 JSON，可能瞬时）。**按政策未产出不进 `failureKind`**；另设 `policyReason` **七值**：`NO_SOURCE_DECLARED` / `POLICY_REJECTED` / `MODEL_DECLINED` / `CONTEXT_UNAVAILABLE` / `CREDENTIAL_UNAVAILABLE` / `SUSPENDED` / `OVERLOADED`（**2026-10-02 由主仓 #104 补本地短路两值**）。**「禁用」不在其中**（无记录可写）。**空装配与策略拒绝必须独立**：前者 = 建模漏配（声明面），后者 = 策略按设计拦下（内容面）；混写会让「策略命中率」失真。

**可观测面（信号契约）**：**错误指标只收「未产出 / 失败」**；`按政策未产出` **独立计数、绝不计入错误率**；重放**独立运维信号、不算错误**；装配器过滤、延迟、token（input / output **分记**）、落盘降级各有独立计数。**维度基数受控**：**不**做 `instanceId` / `decisionId` 维度。**消费三层**：① **始终**写结构化日志（下限，不可弱化）；② **可选 SPI**（应用实现 `DecisionObserver` 一类即回调）；③ **有 Micrometer 才注册指标**（条件装配，**不硬依赖** Actuator，守最小依赖纪律）。**不**把 Spring 事件当契约。**成本只计数、不定价**：token 取自 provider 响应 usage，**缺失不猜、且不设 `unknown` 标记值**（可见性出口 = 独立计数 `tokens.usage.missing`）；未经模型调用（直提 / 非模型端点）**不产生任何 token 观测** —— 「不适用」与「未知」**必须可分**；定价归应用，框架不提供 pricing 钩子。

**（2026-09-26 实现期形态定稿 · 探索期决议「可观测性的实现形态」）** 上段的「信号名 / 维度 / 签名归实现期」部分落定如下，**语义未变**（逐处显式化登记见头部）：

- **单一构造点**：一次「已触发的决策尝试」（拉面）或一次「建议提交」（推面）在结局落定时构造**一条** `DecisionObservation`，日志 / `DecisionObserver` / 指标三面**同值消费**；**不触发**的四类（未激活 / 节点未声明 / 事件面关闭 / 无活锚点）产出**零观测**（观测条数 ≠ 证据行数 —— 池满 / 缺身份 / 锚点失效 / 实例已结束**不落证据行但有观测**）。**唯一例外**：重放计数由写入点判别命中时**直发**、不经构造点（依据：读侧派生事实不得落字段）。
- **观测事实字段（16）**：定位 `taskId` / `nodeId` / `processInstanceId`；结局 `outcome`（**可空** —— 三叶子态为闭集，未物质化的三情形**无结局、不新增第四态**）；分类 `failureKind` / `policyReason` / `severity`；归因 `subjectType` / `modelId`；链路 `chainStage`；计量 `latencyMs` / `inputTokens` / `outputTokens`；未物质化 `writeDegradedCause`（∈{`ANCHOR_LOST`, `INSTANCE_ENDED`}）/ `admissionReason`（`SuggestionAdmissionReason`，未物质化的准入失败下只取 `IDEMPOTENCY_KEY_REQUIRED`）；装配 `droppedContextSources`。**不含** `redacted` / `truncated` / `completeness`（属证据面）。 **（2026-10-02 由主仓 #105 补填值口径，见头部登记）** 归因 `modelId` 与链路 `chainStage` 的**填值口径 = 框架是否确已发起主链路出站调用**（事实判据，不按失败名称粗分类）：已出站（产出 / 模型主动不产出 / 入站加工失败 / 出站失败）⇒ 填响应值（出站失败 `modelId` 不可得留空、`chainStage = PRIMARY`）；未出站（装配失败 / 策略拒绝 / clamp 拒绝 / 目标不可解析 / 暂停 / 池满 / 未物质化 / 未归口兜底）⇒ 保持 `null`。与证据面出处组**同一判据**（**2026-10-02 由主仓 #104 收敛**：原「全组双射判据**有意不同**、**不得互推**」表述**作废**，见头部 #104 登记）。**（2026-10-02 补）** 写入器拒绝草稿后改落的最小化 `INTERNAL_ERROR` 替代行**同此口径** —— 其观测的 `chainStage` 承继**被拒草稿**的值，故替代证据行与观测行在该字段上恒同值（落点 `E13#refusedDraftFallsToMinimalRowThatKeepsChainStage()`）。
- **日志 / 回调**：日志 = SLF4J 参数化 + 固定字段名、单一 logger 常量、每条观测一行、级别 = `severity` 直映；`DecisionObserver` = **普通接口**（非 Spring 事件）、单方法 `onDecision(DecisionObservation)`、多实例集合注入、顺序不承诺、同线程同步调用。
- **观测面禁载**（含由其派生的任何信号）：凭据材料、证据载荷内容（`inputSnapshot` / `rawOutput` / `rationaleNarrative` / `rationaleFacts` 的**值**）、出域载荷内容、`actionSummary`、`subjectId` / `subjectName`、`idempotencyKey`、异常 message 与堆栈、变量名与变量值。**日志可记 `processInstanceId`，指标不可**（维度受控 —— 有意不对称）。
- **计错判据 = `failureKind != null`**：`NO_SUGGESTION_BY_POLICY` 永不带 `failureKind` ⇒ **绝不入错误率**；`INBOUND_PROCESSING_FAILED` 出现在 `SUGGESTION_PRODUCED` 上仍**计入错误**。**框架不定义错误率**（分母由下游自造）。
- **隔离与顺序**：日志 → 指标 → 观测回调，三个消费者各自独立、任一失败**不上抛**、不改变决策结局与流程状态。
- **信号（9）与维度**：见 `docs/impl/0042-verification-landings.md` 的 `E18` 落点；`severity` 为 `DecisionSeverity`（`ERROR` / `WARN` / `INFO`）。

**降级下限**：**观察面 = best-effort** —— 其自身故障只降级到结构化日志，**绝不上抛、绝不改变决策结局或流程状态**；**硬护栏**影响结局但同样**不触流程状态**；**绝不静默**。

**发起前锚点检查（含竞态边界）**：机制**触发前**必须先有**活锚点**（实例存活 + 任务活跃），无活锚点 ⇒ **不触发 → 无记录**（**不新增第四态**，只是把「未触发」的边界前移到发起前）。**竞态边界（须写进 ADR）**：前置检查**只能**压掉「**发起前**已消失」的注定失败，**不能**消除「**发起后运行中**消失」的竞态 —— 后者仍走写入失败 → 降级。

**配置载体**：**节点级声明为主**（护栏与触发同源 —— 按键配在 yml 会漏配、且不随 BPMN 版本走）；**starter 全局默认 + 框架硬上限**为辅。框架硬上限**可由应用调低、不可放大**。

**来自凭据边界的约束**：`OUTBOUND_CREDENTIAL_INVALID` 的判定依据 = Transport 层返回的 **401/403**；凭据解析侧失败折叠进同一枚举（不新增枚举、severity 与重试语义照旧）；该 kind 及其同族**只在框架默认 Provider 路径上成立**，应用替换 Provider 缝后框架不再产出它们，退化为应用自报或 `INTERNAL_ERROR` —— **不得把「替换 Provider 后失去细粒度分类」读作框架失职**。

**来自人工覆盖与复核的约束**：采纳 / 覆盖信号若收，须同时满足 —— ① **不计入错误指标**（它是行为信号）；② 维度含**决策源**与**节点**；③ **不得**为此持久化「采纳判定」（它是派生事实，落库会造出第二份真相）。且 **`AUTO_COMPLETE` 不得被读成「人采纳了建议」**（**读侧须知**：引擎 `CommentType=AUTO_COMPLETE` 经本机制读侧契约面映射后表现为 `action=AGREE`；在无引擎内部类型信息的情况下，机制不保证其与人工 `AGREE` 可判别。`ACCEPTED` 仅表示比较结果同值，不表示人接受了建议）。

来源：探索期决议（运行护栏与可观测性）。

### 11. 兼容与回滚

**结论**：三条性质 —— 默认关闭、关闭后无感、移除扩展不伤核心 —— **成立**，且每条被钉成可验证形态。「回滚」= **停增量**：框架不提供数据回滚，且回滚动作本身**不引入新的失败态**。

**1. 「关闭后无感」= 可观测结局等价，不是运行时零活动。** 五面等价清单（关闭态与「机制不存在」逐面相等）：① 运行时状态与结束态历史；② `getApprovalHistory` 返回值**逐字段相等**（含 `decisionEvidences` 恒为空）；③ 所有写操作返回值与异常；④ 事务语义；⑤ 既有 `ProcessEventListener` 实现收到的回调序列不变。**口径声明（须进 ADR）**：core 仍会构造并发布一个**无订阅者**的 `TaskCreatedEvent`，其可观测边界 = 只有主动实现 `onTaskCreated` 的一方能观测到 —— 故「无感」**不得**被读作「core 运行时零新增活动」。

**2. 三层关闭矩阵**：

| 层 | 管什么 | 关闭的结局 |
|---|---|---|
| 全局启用开关（默认关） | 拉面 + 推面 | 不触发、不留记录、非失败 |
| 节点声明（`decisionEnabled`） | **只**门控拉面与出域 | 未声明节点仍可被外部直提并留痕 |
| 推面 | 无节点级开关 | 只能靠全局关 |

**防误读句（进 ADR）**：**「节点未声明」≠「该节点零决策痕迹」**。

**3. 部署期校验与总闸解耦：validator 始终生效。** **阻断条件（精确表述）** = BPMN 出现本机制扩展属性，**且**该扩展属性**不满足校验规则**。不构成部署失败的情形（穷举）：**①** 本机制扩展属性下**无任何声明**（未声明节点）；**②** 全局启用开关关闭**且该模型内本机制声明内容全部合法**；**③** 节点声明残留但**内容合法**。**唯一显式例外**：*仅当 BPMN 出现本机制扩展属性且不满足校验规则时，才出现部署期行为差异* —— 这是「关闭后无感」在全图中唯一的例外，其余五面一律等价。选此而非「关即不校验」的理由：命中条件仅「写了本机制扩展属性」，对从未书写者零影响；而休眠错配的代价更高（打开总闸当天才在部署期炸）。**（2026-09-25 显式化：穷举 ② 的限定语由本节「唯一显式例外」句收敛而来 —— 全局启用开关的取值**不进入**校验判定，「开关关 + 声明非法」**仍阻断**；详见头部登记。）**

**4. 「移除 extension 不伤 core」的残留账本**（optional 依赖只保证**装配消失**；**四行内建 Core 残留**逐条登记 —— 此处账本**不含部署期 / 业务注入的自定义扩展**，如按第 3 条注册的自定义 `Validator`：那类扩展属 Extension、随装配消失，不属 Core 固有残留；四行均承诺**无数据时零副作用**）：

**「零副作用」的定义（2026-09-25 受限重开 · 澄清，不改变强度）**：**无状态变异**（不改写流程状态 / 历史 / 变量）＋ **无外部副作用**（不向外发射本机制语义上的事件）；**允许内部只读探活**（既有 `EventBus` 一类的内部检查）。故四行的承诺**不得**被读作「core 运行时不得发生任何新增活动」—— 与第 1 条「无感 ≠ 运行时零活动」同旨。

**证伪句**：若某条残留的「无数据时行为」**改写了流程状态 / 历史 / 变量**，或**对外发射了本机制语义上的事件**，则本定义被证伪，本条澄清作废。

| # | 残留 | 无数据时行为 | 是否需清理 |
|---|---|---|---|
| ① | `TaskCreatedEvent` + `ProcessEventListener.onTaskCreated` default + `EventBus.taskCreated()` | 仍发射，无订阅者即无副作用 | 否 |
| ② | `CommentType.DECISION_EVIDENCE` + 并列第三组常量 | 枚举值存在，无写入 | 否 |
| ③ | 读侧 `DecisionEvidenceVO` 类型 + `ApprovalRecordVO` / `CountersignSubRecord` 各一个 `decisionEvidences` 字段 + 各一个读侧**派生判定方法**（`resolveReplayOf`，判定语义、**不落字段**） | 类型存在，字段恒返回空集合（派生面恒无输入，不产生标注） | 否 |
| ④ | 读侧**一处实改**（`findFirstBusinessComment` 第二遍加证据组排除）+ **两处结构性已排除**（`findFirstOperationComment` / `findAllOperationComments` 经包含式集合过滤）+ `CommentTypeConverter` 显式 `case` + 守卫测试 | 无标记行可排除，等价现状 | 否 |

不撞 ADR-0030：core 事件 SPI 的消费者一直是下游 / 扩展（既有事件同形）。

**5. 回滚四层口径**：

| 层 | 动作 | 结局 |
|---|---|---|
| (a) 全局开关置 false | 配置 | 停增量，存量证据保留 |

### 12. 人工覆盖与复核

**结论：零新增机制；新增的是一条可复核的定义。** 不新增任何覆盖 / 复核 / 撤回的**动作**、记录类型、读侧槽位、字段或接口。实质产出是把「人工覆盖」从**叙述**变成**可被第三方复现的判定规则**。

**覆盖留痕的载体 = 既有人工意见本身**：否决 / 覆写由人通过**既有审批动作**表达，它本来就必然留痕。框架**不提供任何「无痕覆盖」的通路**。**否决方案一**：复用 `operationComments` 槽（该槽语义已被操作注释占用，混入判定类意见正是槽位竞争）。**否决方案二**：新增第四个读侧槽位（与「单一审计面」冲突，并给 core 添改动）。

**不对称写在明处**：建议侧**可多条**（外部、异步、不受框架控制）；人的决定侧**单槽**（core 既有读侧语义：`comment` 取业务意见组首个）。故本机制承诺的判定是「**该锚点读出的人侧动作 × 该锚点全部建议**」，**不承诺「覆盖历史」的全量可读**。

**采纳判定（四值）**：

| 取值 | 含义 |
|---|---|
| `ACCEPTED` | 建议动作与该锚点读出的人侧表态**同值** |
| `NOT_ACCEPTED` | **异值**（否决与覆写在此同值，契约不区分） |
| `NOT_COMPARABLE` | 该锚点**有**人侧动作，但它不是表态 |
| `UNDECIDED` | 该锚点**尚无可读的人侧表态** |

**表态比较面**（人的一侧只认四个动作）：`AGREE` / `REJECT` / `COUNTER_SIGN_AGREE` / `COUNTER_SIGN_REJECT`。**显式排除**：`RETURN` 退回、`WITHDRAW` 收回待办、`INVALID` 作废、`AUTO_COMPLETE` 自动提交、`INITIATE_COUNTERSIGN` 发起会签，以及整个操作注释组。承重条款是 **`AUTO_COMPLETE` 必须排除** —— 它是自动提交（机器产出），且现契约把 `AUTO_COMPLETE → AGREE` 折算；若沿用该折算入比较面，「机器自动通过」就会被读成「人采纳了建议」。

**`AUTO_COMPLETE` 排除的固有层（2026-09-25 裁定）**：排除**不在动作读取结果层成立**。读侧契约面（`getApprovalHistory` 的 VO）**不承载**原始 `CommentType`，`comment` 槽位是业务意见文本、`action` 槽位是映射后动作；`CommentType=AUTO_COMPLETE` 经映射后表现为面内的 `action=AGREE`，在无引擎内部类型信息的情况下**不保证**与人工 `AGREE` 可判别。故本机制**不能**对 `AUTO_COMPLETE` 作独立动作层断言 —— 本条**不是一条可执行的排除规则**，而是**已知边界**（见「不做 / 已知边界」），**不得**被读作「机制已排除 `AUTO_COMPLETE`」，也**不得**据它推论「`ACCEPTED` 即人接受了建议」。

**同族的第二条已知边界（2026-09-25 增登）**：动作层 `AGREE` 另有**非评论来源** —— `inferAction` 三级兜底 `deleteReason="completed" → AGREE`（`DefaultActionInferenceStrategy`）：**既无业务意见、也无操作注释**的完成会被读成 `action=AGREE`。它与 `AUTO_COMPLETE` **同族而不同源**（一个来自 `deleteReason`、一个来自 `CommentType` 映射），同样使采纳判定在**同值**时读出 `ACCEPTED`。处置：**登记为已知边界，不在本机制内修**（修它要动 core 既有读侧推断语义，越出本机制）；「`ACCEPTED` 仅表示比较结果同值，不表示人接受了建议」这条收窄对它同样适用。

**判定的落点与推导**：① **不落字段、不给 API、v1 不做读侧计算** —— 它是契约定义的**派生事实**（叫**采纳判定**，不叫「采纳状态」，它随读取时刻变化）；框架**不提供**任何计算它、暴露它、缓存它的 helper 或字段 —— 一旦提供，它就成为事实上的公开面。② **锚在 core 既有读侧槽位**，不是「时间上最新」；③ **跨锚点不承诺**。

**复核 = 读侧既得承诺**：同一锚点上，建议证据 + 人工决定 + 时序 + 来源可在同一次审批轨迹读取中被第三方并列读取。**不引入**「复核」一等概念、复核状态，或「复核人 ≠ 决策人」的框架级约束（那是应用的工作流建模）。**承诺收窄**：只承诺**覆盖动作可复核**，**不承诺人侧身份的可靠性**（见「不做 / 已知边界」）。

**晚到建议 × 已发生的人工决定**：允许晚到建议写入证据组；**不新增「晚到」标注字段、不新增 `late` 状态、不新增 `post-decision advice` 类型**。读侧按时间序呈现，第三方靠时序即可辨别。

**自动化偏见：只钉 A（结构性非等价化）** —— 建议不占人工意见槽位、不自动成为决定、不提供从建议到流程推进的便捷通路、**不引入强制逐条确认**、**`AUTO_COMPLETE` 不得被读成人的采纳**（**读侧须知**：引擎 `CommentType=AUTO_COMPLETE` 经本机制读侧契约面映射后表现为 `action=AGREE`；在无引擎内部类型信息的情况下，机制不保证其与人工 `AGREE` 可判别。`ACCEPTED` 仅表示比较结果同值，不表示人接受了建议）。依据：2,784 人随机实验显示「要求人工纠错**反而**降低参与度、提高错误接受率」—— 干预式设计会把复核变成橡皮图章。**否决 C（置信度展示 / 风险高亮 / 必须复核才放行）**：同依据，方向相反。

**撤回**：**v1 不提供任何撤回动作**。**反悔 = 追加一条相反的人工决定**（与主仓既有先例一致：`withdrawTask` / `invalidateProcess` 都写一条新意见，不改写历史）。**拆词（钉死）**：主仓的**撤回**（`WITHDRAW`，上一节点收回待办）与**作废**（`INVALID`）是**流程级动作**、会改流程状态，与「反悔」不是同一件事；二者**同名不同物**，不得合并成一条词条、不得互相替代。

**监管能力 × 落点**：监视 → 可观测面；解释 → 决策证据；覆写 → 本机制（采纳判定 + 并置可读，框架不提供动作）；暂停 → 运行暂停（落 `NO_SUGGESTION_BY_POLICY`）+ 引擎既有实例挂起；four-eyes → 应用侧工作流建模，框架不引入；automation bias → 上述 A。

**零新增核对**：core 零改动；extension 零新增类型；starter 零改动。

来源：探索期决议（人工覆盖与复核路径）。

### 13. 边界可控的验收闸门（kill switch 2）

**kill switch 2 立为可判定闸门。** 判定对象 = **三条承重边界**（能力 / 失效 / 退出）的**四条承重不变量**能否被**主动击穿实验**判定 —— **不是**「验收矩阵全绿」。本 ADR 阶段交付「**可执行且非循环**的判定程序」；**实测留实现期，实测结果是本 ADR 的撤销条件，不是放行条件**。举证责任**不外**包给任何沙盒。

**四条承重不变量**（边界是**域**，不变量是**域内否命题**）：

| id | 归属边界 | 措辞 |
|---|---|---|
| **I1** | 能力边界 · 流程状态面 | 不存在任何框架通路，使一个未经「建议提交」留痕的动作改变流程状态 |
| **I2** | 能力边界 · 数据离域面 | 不存在任何框架通路，使一份未经「出域控制」的数据离开本域 |
| **I3** | 失效边界 | 任何未产出都留下可区分的结局，绝不表现为无事的正常通过 |
| **I4** | 退出边界 | 机制未激活、或关闭 / 移除之后，不产生任何决策活动或出站调用 |

**适用域（域界定）**：I1 / I2 的「框架通路」**限定在本机制** —— I1 指「**本机制不存在任何通路，使一个未经「建议提交」留痕的动作改变流程状态**」；I2 指「**本机制不存在任何通路，使一份未经「出域控制」的数据经「决策目标」的出站链路离开本域**」。既有的 `AutoApprovalRule` 自动提交路径（GA 行为、同步、老路径）**不在** I1 的适用域内 —— 它与本机制**可证伪地隔离**（无类型引用 / 无实现 / 无适配器 / 无桥接 / starter 不装配通路），其失败语义分歧已由第 8 节记为**有意分歧**。应用侧以**不经本机制承载、触发或承诺为出站链路**的自有路径消费 `suggestedAction` 或发起出站调用，**不在 I1 / I2 的适用域内**；**但**该路径一旦被本机制用作决策目标出站链路，或承载**本机制「出域控制」应覆盖的数据路径**，**仍受 I2 约束**。

**登记说明**：本域界定**显式化**自立闸时的既有域（`CONTEXT.md`「决策活动」= 本机制产生的活动；靶子① 的对抗尝试只在机制内成立），**未改写任何不变量的适用域**、**未扩台账类型闭集**（住所 = 本 ADR 正文 + 执行面正文）。若日后维护者要改动该域，按 §5.5「球门修订」另行显式登记。

**边界分界**：**退出边界**管「**未激活**、或**曾激活后被关掉 / 移除**」；**能力边界**管「机制**一旦激活**，其流程状态面与数据离域面仍不得被击穿」；**把节点的启用声明关掉**属 I4 的「关闭」，不属「未激活」。

**最小术语钉（防实现期扩大 / 缩小）**：**出站调用** = 框架经「决策目标」发出的调用，不含出域策略的本地纯计算与入站加工，**也不含不承载决策效力的日志、指标等失败观测信号**；**决策活动** = **本机制**产生的活动（建议提交 / 决策证据留痕 / 拉管线发起 / 装配 / 出站调用），**不含** core 侧那个无订阅者的 `TaskCreatedEvent`；**未激活** = 全局开关关闭，或机制未装配 / 移除 extension，**显式排除「节点未声明」**；**离开本域** = 数据经「决策目标」**进入出站调用载荷，或到达外部系统**，**不要求调用成功**（钉到**通道面**而非结果面，否则「载荷已成形但调用失败」会出现假阴性）；**通过**（I3 的否定项）= 流程状态发生改变 **∨** 审批轨迹上出现一条人工意见。

**举证形态**：**八项靶子不合并、一实验一断言**，与四条不变量**满射覆盖**（每项靶子 ≥1 条不变量、每条不变量 ≥1 项靶子；**不是一一对应**）：① 无证据推进 ② 越域出站 ③ 影子活动 ④ 故障注入 ⑤ 重放 ⑥ 覆盖 ⑦ 三层关闭 ⑧ 校验例外。**准入条件 ①–⑥**（不满足者即便越界也不算命中）；**同构变体通道**（四条同构判据同时满足才可登记，**变体扩的是实验集，不是结论集**）。正面断言矩阵为**回归配套**，不参与本闸门裁定。

**失败程序与状态**：**判据三条** —— ① 某条不变量写不出满足准入的击穿实验；② 某条击穿实验达到准入且**越界成功**；③ 判定程序**引用未裁定结论**（循环论证）。**分层退回**：与三条判据一一对应，见本节「**分层回退**」（**单一住所**，此处不重述）。**临时冻结** = 开发 / 发布层面的安全操作路径（**任何实现者可单方冻结、不得解冻**；解冻与最终裁定归**维护者**），运行期表现**复用既有「禁用」**，**不开第三个运行期状态**。**状态闭集** = `草稿` / `已放行·附撤销条件` / `疑似命中` / `作废`（**闭集里没有裸 `已放行`**）；**「收缩」是处置结果、不是状态**，仅为 `作废` 的替代结局。**词面映射（主仓头部词 ↔ 本闭集词）**：主仓头部状态词写作 **`已接受（附撤销条件）`**，即本闭集里的 **`已放行·附撤销条件`** —— 两词**同义**，**状态数不变**；本节以下一律用闭集词形。

**放行生效序**：本 ADR 的放行**自域界定登记完成起生效**；登记完成前，I1 / I2 相关段落**不构成实现期冻结的依据**。

**撤销条件**（是放行的条件，不是放行的依据）：本 ADR 的放行**附撤销条件**。下列任一在实现期发生，即由**主仓维护者**裁定转入 `疑似命中`：

1. 任一条承重不变量（I1–I4）的**具名击穿实验**满足准入条件 ①–⑥ 且**越界成功**（判据②）——**含**「域界定被证不足、按字面读成立的越界通路仍成立」这一情形；
2. 判定程序被证明**引用了未裁定的结论**（判据③）。

**分层回退**（与判据一一对应，不一刀切）：

- **判据②** ⇒ 机制退回「不做」，或按既有降级决议**收缩**为「只留痕、不承载」。`疑似命中` 之后的**处置结果**由**维护者**裁定，可包括**恢复为 `已放行·附撤销条件`**、裁定 `作废`，或**收缩为「只留痕、不承载」** —— 其中**「收缩」是处置结果，不是新增状态**。
- **判据③** ⇒ **重写判定程序**，机制**不退回**。
- **判据①**（实现期发现某条不变量**写不出**满足准入的实验）⇒ 该不变量**回炉 + 另立新案**，机制**不砍**、**不进冻结态**。

**撤销权归主仓维护者**；任何实现者可**单方冻结、不得解冻**。

**登记位**：本节的状态变化（命中 / 冻结 / 裁定）一律以**主仓 issue** 登记，标题前缀 **`[ADR-0042 撤销]`**；**不预置常驻 issue** —— 无命中即无 issue。

**居所**：裁决面（不变量、闸门条款、状态集）进本 ADR；执行面（靶子矩阵骨架 / 不验收项对账 / 台账）落 `docs/research/kill-switch-2-acceptance-gate.md`；回归断言进主仓 CI（**不新增矩阵轴**）。

**P2 受控压力测试探针**：一个 BPMN **两边同挂**（既有 `AutoApprovalRule` 老路径 + 本机制节点声明），落 **starter 集成测**，四断言（老路径逐字段等价 / 本机制侧无自动提交痕迹 / 从 `suggestedAction` 到流程推进无框架通路 / 默认关下不激活）。**不放沙盒。**

**不验收项清单（不是豁免书）**：逐条**附「不变量保持论证」**、注明归属不变量；**不接受总则式声明**。论证不出来者**默认升为承重靶子**并进入冻结判定；改写不变量适用域属「球门修订」，只有维护者可做且**必须显式登记**。清单条目**一律不得**触及 I1–I4 本身。

来源：探索期决议（边界可控的验收方案）；**放行裁定**：探索期决议（kill switch 2 闸门裁定，2026-09-25）。

## 不做 / 已知边界

### 不做

- **时间维度（「挂起—续跑」）——不做**。「决策在实例存在后异步到达」这一**事实面**由既有 BPMN 等待态与引擎持久化契约承载，并被本 ADR 既有的一致性要求**吸收**；框架（含 extension）**无需**另立一等「挂起—续跑」机制。

  **证伪句（关闭附带解除条件，仍可证伪）**：

  > 在 flowable-plus 的栈里，「决策在实例存在后异步到达」可由既有 BPMN 等待态（用户任务 / 接收任务 / message catch / timer）与引擎持久化契约承载，且**不丢失任何由框架契约承诺的属性**（失败 / 回滚 / 重试 / 覆盖 / 续跑下仍成立）—— 故框架（含 extension）无需另立一等「挂起—续跑」机制。**若存在一种表达，应用侧用它表达同一件事时必然丢失某项引擎契约承诺的属性，本结论即被推翻。**

  **解除条件**：反例须**同时**满足 kill switch 1 的五条。仅「应用能塞 JSON、能自建表、能自己保证一致」**不算击穿**。

- **术语边界：等待态 ≠ 行政挂起**。**等待态** = 流程逻辑上停在节点等事件（用户任务 / 接收任务 / message catch / timer），状态持久化、不占线程、事件到达即续跑 —— 「决策在实例存在后异步到达」对应的是这一类；**行政挂起** = `RuntimeService.suspendProcessInstanceById` 冻结实例（关联 job 不执行）、`activateProcessInstanceById` 恢复 —— **与决策到达无关**，是引擎既有的一等 API。**为何要钉开**：不区分会让「引擎已有一等挂起」被误读成「等待态也已一等」，或反之 —— 这正是上条「不做」结论最容易被读错的地方。（一手核对：`flowable-engine-6.8.0-sources.jar` 中 `RuntimeService` 的 javadoc 明示 suspended 态不执行关联 job。）

- **v1 不做流式（SSE）**（见「决策」第 4 节）。
- **v1 不提供任何撤回动作**（见「决策」第 12 节）。
- **v1 不交付任何公共的非 AI 生产件**（见「决策」第 3 节）。
- **熔断、定价、数据回滚**归应用或不做（见「决策」第 10 节、第 11 节）。
- **v1 不支持无任务锚点的证据**（见「决策」第 5 节）。

### 人侧身份可靠性（core 侧 `USER_ID_` 写入点缺失）——**不修 / 已知边界**

**结论**：本机制对人工侧只承诺「**是否被覆盖**」，**不承诺**「**被谁覆盖**」的身份可靠性。「被谁覆盖」由 core 公开读侧承载，本机制**引用但不承诺**。`ACT_HI_COMMENT.USER_ID_` 的**存储层独立可追溯**，同样不作为本机制的承诺。

**已核实事实**（一手：`flowable-engine-6.8.0-sources.jar` + 主仓工作树）：

- 评论行的 `USER_ID_` 由 `AddCommentCmd` 写入，取值 `Authentication.getAuthenticatedUserId()`（`SaveCommentCmd` 不写）；
- 主仓仅 `ProcessLifecycleWorkflow.startProcess` 调用 `identityService.setAuthenticatedUserId(...)` 并在 `finally` 置空，其余工作流无一处设置 ⇒ **除 `startProcess` 作用域（含其内的 `AUTO_COMPLETE`）外，人工动作写下的评论行 `USER_ID_` 一律为 null**；
- 读侧 `ApprovalRecordVO.actorId` 取自 `task.getAssignee()`，**不读评论行**；写侧对人工动作强制 `task.assignee == userContext.getCurrentUserId()`（`TaskValidation.validateCurrentUserIsAssignee`，同意 / 驳回 / 跳转 / 会签均过此闸）。

**引用前提（本机制引用 `actorId` 时成立的条件，须随引用一并声明）**：该引用的可靠性建立在上述**写侧校验**之上 —— 经 flowable-plus 门面操作时 `assignee` 恒为操作人。**该前提不由本机制承诺、也不由本机制维护**；绕过门面直调引擎 API 的情形不在本机制承诺面内。

**第三方口径**：判定「建议是否被覆盖、被谁覆盖」的公开且契约化入口 = `getApprovalHistory` 的逐字段产出（`actorId` + `action`）× 决策证据 JSON（`suggestedAction`）。二者均为框架公开产出，故满足 kill switch 1 条件⑤ 的「无需实现方内部知识即可验证」。

**归因边界**：`actorId` 不可靠**不构成** kill switch 1 条件⑤ 的击穿 —— 条件⑤ 的被验对象**止于本机制自身产出的留痕**，不含 core 既有 `actorId` 的可靠性。

**不构成缺口的情形（穷举，防误记）**：`actorId` 为 null 有两种**结构性**来源，**不属**本条所指缺口 —— ① 活动无关联任务（`HistoryWorkflow.buildRecordWithoutTask` 的兜底）；② 会签轮次父记录（`buildRoundVO` 的父 `actorId` 结构性为 null，子记录各自携带主体）。

**触发条件（非无条件悬置）**：若将来审计 / 监管口径要求**存储层独立可追溯**，该需求归**主仓另案**（形态：补 `UserContext.getCurrentUserId()` → `identityService.setAuthenticatedUserId` 的写入点，或新增身份登记面）。**本 ADR 不承诺、不代偿**。

## 备选方案

**技术底座**：引厂商 SDK（**否决** —— 锁厂商，与厂商中立冲突）；RestTemplate（**否决** —— 需引 `spring-web`，会把 Spring Web 拖进 extension）；由 Hutool 承担 HTTP 层（**否决** —— Hutool 在推荐轮子清单里的定位是兜底，HTTP 场景存在 Apache HttpClient 这一对应选择）；v1 承诺流式（**否决** —— 与证据快照冲突，属表现层）。

**契约形状**：与原 SPI 并列 / 包裹 / 独立于自动提交链路（**都不是** —— 是互补的另一半机制）；把依据塞进 `Map` / 裸 `String`（**否决** —— 撞 ADR-0015 反模式，且 kill switch 1 条件② 无法证）；扩原 SPI 的返回契约（**否决** —— 已定前提，且属 GA 破坏性变更）。

**证据落点**：证据另开接口 / 新增表（**否决** —— 条件⑤ 不可证 + 框架首张自建表 + 与既有演化手法不同构）；经 `CommentEntityManager` 直插 `ACT_HI_COMMENT` 绕过校验（**否决** —— 破坏事件派发 / 审计语义 / 事务与并发控制）。

**覆盖语义**：复用 `operationComments` 槽（**否决** —— 槽位竞争）；新增第四个读侧槽位（**否决** —— 与单一审计面冲突，且给 core 添改动）；引入「撤回」动作（**否决** —— 立刻要元状态，而元状态没有落点）；把采纳判定落成字段 / 给 API（**否决** —— 它是派生事实，落库会造出第二份真相）。

**通用化**：为「决策源」开一等类型 / 注册面 / SPI（**否决** —— 给同一职能开第二个入口）；为推面新增「不需要 target 的启用位」（**否决** —— 同上）；让 `decisionEnabled` 的含义取决于有没有写 target（**否决** —— 跨属性推断，与「绝不隐式」相反）；开放 `subjectType` 取值（**否决** —— 出处不可被第三方稳定识别，且框架无法为未知类别承诺语义）；把 `USER` 从 v1 值域拿掉（**否决** —— 公开枚举上做两次破坏性变更）。

**运行护栏**：框架自带熔断器（**否决** —— 策略归应用，跨实例阈值是应用的策略）；框架提供定价钩子（**否决** —— 只计数不定价）；引入**待重试态**（**否决** —— 异步调度需跨时长持久化队列，越界）；把 Spring 事件当契约（**否决**）。

**兼容与回滚**：框架提供数据回滚（**否决** —— 不需要，读侧标记驱动）；「关即不校验」（**否决** —— 休眠错配代价更高）；移除 extension 时让 `decisionEvidences` 编译失败（**否决** —— 软回退是有意选择）；用金样本文件做对拍（**否决** —— 随版本漂移变成维护负担）。

**沙盒与验收**：把沙盒作为 P2 探针承载地（**否决** —— 探针议题归验收决议）；把 kill switch 2 的举证责任外包给沙盒（**否决**）；把探索工作区做成可编译工程（**否决** —— 纯文档探索仓，构建根的成本远超证据价值）；recorded 录放进 v1（**否定** —— 录制需要真实 key，恰是要避免的 CI 前提）。

## 后果

**正面**：

- 框架获得一个**公开且契约化**的位点，使流程外异步到达的决策其依据 / 出处 / 主体以框架承诺的方式留存，并与流程状态共享同一一致性承诺。
- 与既有 `AutoApprovalRule` **可证伪地隔离**（无类型引用、无实现、无适配器、无桥接、starter 不装配通路），既不改动 GA 契约，也不制造双轨。
- 契约**决策源中立**：三面（生产者开放 / 归因稳定可识别 / 生产者无需可被框架调用）都是**契约性质**，不依赖 v1 恰好交付了哪种生产者。
- **默认关闭 + 关闭后无感 + 移除不伤 core** 三条性质被钉成可验证形态，回流主仓的风险面收敛。
- 边界可控性有**可判定闸门**（四条承重不变量 × 八靶子），实测结果作为撤销条件而非放行条件。

**负面 / 风险**：

- **动 core**：`CommentType` 新增枚举与常量组 + 读侧三处推断排除 + VO 两处**承载面**（字段 + 派生判定方法 `resolveReplayOf`）+ `TaskCreatedEvent` 及其回调 / 发布方法 —— 共**四行内建 Core 残留账本**（**不含**部署期 / 业务注入的自定义扩展，如自定义 `Validator`），随 extension 移除而仍在。
- **新增一个依赖**（Apache HttpClient）；extension 现有 `hutool-all` 的去留**已定** —— extension 删其**未使用**声明，core 侧 3 处 `StrUtil` 的替换面属**主仓依赖账本**、本机制不代裁（见头部登记，探索期决议「模块与构建的实现形态」）。
- **新旧失败语义有意分歧**，读代码的人若不知情会以为漏了 —— 故必须写进本 ADR。
- **部分边界与 kill switch 1 条件⑤ 相冲**（任务已消失时「未产出」在审批轨迹上不可见），已具名登记为已知边界，不掩盖。
- **推面准入失败纳入错误指标**：直提方的提交错误（三项前置带齐者）现物质化为 `SITE_ADMISSION_REJECTED`，按其 `severity = ERROR` **进告警并计入错误指标** —— 与拉面对称，代价是**应用侧提交参数错误会变成框架侧告警噪声**（框架不定义错误率，分母由下游自造）。**不落行的例外**是未带齐三项前置者（日志 + 指标）。
- **人侧身份可靠性不承诺**，第三方若要「存储层独立可追溯」，须主仓另案。
- 实现期负担不轻：守卫测试四落点、三档防御、中立性清单五面、八项击穿实验、P2 探针。

**放行状态**：本 ADR 已由**主仓维护者**裁定为 **`已接受（附撤销条件）`**（2026-09-25）—— kill switch 2 的三条判据逐条过完，**均不命中**。**撤销条件与分层回退**见第 13 节；**放行自域界定登记完成起生效**。
