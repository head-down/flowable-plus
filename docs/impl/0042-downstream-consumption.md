# 0042 下游消费面 —— 读侧产出如何被 UI 消费

> **日期**：2026-09-26
> **来源**：本文件**无探索期决议来源** —— 它是「下游接入效果原型」对齐的副产品，不属任何探索期决议的产物（与 `docs/impl/` 其余文件的出处形态不同）。剥出它的理由：`docs/impl/` 原缺**读侧数据的消费面**这一角（既有文件讲产出侧，无人回答「下游拿到 `decisionEvidences` 之后该怎么用」）。原型本体**不进探索工作区** —— 它含真实下游业务语料（业务字段 / 菜单结构 / 页面布局），按 CODEBUDDY.md 的可公开书写纪律不可落库，且随下游页面演化快速过期；留给它的用途是接入期做**对拍探针**，不是文档。
> **定位**：本文件是**读侧产出消费面的唯一住所** —— 承 ADR-0042 第 5 节与第 12 节，回答「下游拿到 `decisionEvidences` 之后该怎么用、什么不能做、哪些是陷阱」。给它一套读侧数据，它能判「UI 该怎么渲染、算不算做错」。
> **与既有 impl 文件的分工**：`0042-module-and-build.md` / `0042-verification-landings.md` 讲**产出侧**（怎么写、住哪、怎么测）；本文件讲**消费侧**（下游前端怎么读、怎么画）。两者不重叠。
> **ADR-0042 侧零改动**：本文件不新增契约、不收窄也不放宽任何 ADR 条款，只把已冻结的读侧事实翻译成消费面的表述。
> **写作纪律**：按可公开标准书写 —— 不含真实下游项目名 / 公司名 / 人名。§3–§4 的举例一律用中性业务（采购申请审批）。
> **前置事实**：ADR-0042 第 5 节（决策证据：单一审计面 + 只读证据组）· 第 8 节（失败后果）· 第 9 节（幂等与回放）· 第 11 节（兼容与回滚）· 第 12 节（人工覆盖与复核）。

## §1 唯一数据入口

| 项 | 事实 |
|---|---|
| 入口 | `getApprovalHistory`（ADR-0028 唯一读入口）。**不另开接口、不新增表、不伪装成人工审批意见**（第 5 节） |
| 承载 | 独立字段 `decisionEvidences`，挂在 `ApprovalRecordVO` / `CountersignSubRecord` 上；`CommentType` 新增 `DECISION_EVIDENCE`（**决策源中立**，不绑 AI） |
| 原始存储 | `ACT_HI_COMMENT`，载荷 = 纯前缀标记 + JSON；读侧剥标记后解析 |
| 换开关的形态 | **软回退**：移除 extension 后**结构仍在、内容为空**（第 11 节）。下游拿到**空集合**而非编译 / 运行错误 |

**由此推出两条消费面义务**：

1. **必须能渲染空集合** —— 不是错误态，是正常态（extension 未装配 / 全局开关关闭 / 该节点未声明）。
2. **读侧容错是字段级的**（第 5 节）：判别式不可解析或载荷损坏 ⇒ 该条证据**跳过投影**，但**审批轨迹行本身不得消失**。次要枚举取值未知 ⇒ 只降级为 `null`，该条证据仍投影。UI 对 `null` 字段必须按「未知」渲染，不能当空串或当成 0。

## §2 UI 上必须区分的五种情形

`outcome` 三叶子态 + 一种**不存在**的情形。五者的用户可见语义完全不同，**不得合并**：

| 情形 | `outcome` | UI 该说什么 | 不能说什么 |
|---|---|---|---|
| 产出建议（经出站调用） | `SUGGESTION_PRODUCED`（A 列） | 显示建议动作 + 摘要 + 依据 | — |
| 产出建议（直提） | `SUGGESTION_PRODUCED`（B 列） | 同上，但**出处组三字段恒 null**、`inputSnapshot` 恒 null | 不显示「模型 / 提供方」（本列无此项） |
| 按政策未产出 | `NO_SUGGESTION_BY_POLICY`（C 列） | 「按政策未产出」+ `policyReason` 的七值之一 | **不说「失败」** —— 其中六值（`NO_SOURCE_DECLARED` / `POLICY_REJECTED` / `CONTEXT_UNAVAILABLE` / `CREDENTIAL_UNAVAILABLE` / `SUSPENDED` / `OVERLOADED`）**结构上未发生出站调用** |
| 产出失败 | `SUGGESTION_FAILED`（D 列） | 「产出失败」+ `failureKind` + **计入错误指标** | 不说「系统拒绝了这个申请」—— 它只说明**建议没产出**，流程状态未动 |
| **未触发**（无该行） | —— | **不显示任何 AI 元素** | **不说「失败」、不说「拒绝」** —— 这是关闭状态（无痕），见 §7 第 3 条 |

**A / B 列的判别不是调用方自述**，而是提交路径的**结构性事实**：拉管线路径必有决策目标，直提路径必无（第 5 节）。**UI 不参与判别，只按字段是否为空渲染。**

**C 列内部还要再分一刀**：`MODEL_DECLINED`（模型主动不产出，**走过**模型调用）⇒ 出处组必填；其余六值（**未发生**出站调用 —— 其中 `CONTEXT_UNAVAILABLE` / `CREDENTIAL_UNAVAILABLE` 是 Provider 侧「本地短路」，属「根本没送出去」而非失败）⇒ 出处组必须 null。UI 若把两者画成同一种「无建议」，就把「模型看过但没说」和「根本没送出去」抹平了。

## §3 字段 → UI 元素的映射

`DecisionEvidenceVO` 是**单一类型 + `outcome` 判别式**（第 5 节）—— 一套字段读三种结局。下表按「能画什么」组织；必填性按四列矩阵（第 5 节），**下游不需要背矩阵，但要知道哪些格子会是 `null`**。

| UI 元素 | 消费字段 | 何时为 `null` |
|---|---|---|
| **建议动作**（通过 / 驳回） | `suggestedAction` | C / D 列恒 null；**UI 必须能画「无动作」** |
| **一句话摘要** | `actionSummary` | 同上（给**人**扫视，**不是判定权威**） |
| **逐条依据** | `rationaleFacts`（类型化，含 `DecisionRationaleFactKey`） | D 列恒 null |
| **依据叙述** | `rationaleNarrative`（文本兜底） | D 列恒 null |
| **出处**（提供方 / 链路阶段 / 是否降级） | `provider` / `chainStage` / `degraded` | **B 列三者恒 null**；C 列仅 `MODEL_DECLINED` 有值 |
| **主体**（谁产出的） | `subjectType`（AI / SYSTEM / USER）+ `subjectId` / `subjectName` | `subjectId` / `subjectName` **可空** —— 判别式是 `subjectType`，ID 与显示名是描述性字段 |
| **完整度**（出域 / 入站各一套） | `outboundRedacted` / `outboundTruncated` / `outboundCompleteness`；`inboundRedacted` / `inboundTruncated` / `inboundCompleteness` | 四列皆必填。**按方向分记**：`outboundCompleteness` ∈ 三值、`inboundCompleteness` ∈ 四值（多一个 `RESTRICTED`） |
| **失败分类** | `failureKind` | 仅 D 列必填；**例外**：`SUGGESTION_PRODUCED` 下唯一允许 `INBOUND_PROCESSING_FAILED` |
| **政策原因** | `policyReason`（七值） | 仅 C 列必填 |
| **时间**（每条证据自己的） | `recordedTime`（**读侧填充**，写侧不产出） | **不进 JSON** —— 由评论行 `TIME_` 列填充（第 5 节）；**恒有值**（评论行恒有 `TIME_`），可直接渲染「这条证据发生在何时」。**不要**拿它排序：顺序由读侧已建立的**列表序**承担（同一毫秒并列本无客观先后，判序细节见 ADR-0042 第 9 节） |
| **幂等身份** | `idempotencyKey` | 四列皆必填；下游若要画「这是重放」，见 §5 |

**两条不变量，UI 不得自行兜底**：

- `suggestedAction` 与 `actionSummary` 冲突时，**一律以 `suggestedAction` 为准**（前者给机器、后者给人）。
- 标志与 `completeness` 的互锁是**写入侧**契约（框架恒填）。读侧因版本错配降级出的 `null` **不触发**它 —— UI **不要**用标志去反推完整度。

## §4 挂载层级：一条证据挂一处

| 节点形态 | 挂在 | 父 VO 的该字段 |
|---|---|---|
| **非会签节点**（读侧无子记录） | `ApprovalRecordVO.decisionEvidences` | —— |
| **会签节点** | 对应的 `CountersignSubRecord.decisionEvidences` | **恒空** |

**同一条证据不重复挂两层**（第 5 节）。三个连带后果：

1. **UI 不能只在父 VO 上找** —— 会签节点上父 VO 恒空是正常形态，不是数据缺失。
2. **「证据行数 ≠ 决策次数」的说明，必须写在证据实际所在的那一层** —— 会签节点上写进子记录，非会签节点上写进父 VO。
3. **锚点是 `taskId`，且是结构性必备**：一条合法准入的提交必然存在当前任务；v1 不支持无任务锚点的证据（第 5 节）。**`ACT_HI_COMMENT` 没有节点列**，节点级锚定无法从行内容推断 —— 所以 UI 只能按读侧已挂好的位置渲染。

**重放标注是派生事实，不是字段**（第 9 节）：同一锚点内按键分组，最早 = 原行，其余标为「重放」并指向原行。派生由**框架读侧**提供（`resolveReplayOf`），下游**不自己算** —— 自己算会与框架承诺的值分叉。`ID_` 不可解析（应用替换了 `IdGenerator`）⇒ 该锚点**整体不判**，下游须能渲染「无标注」这一形态。**框架不抑制重复**：重复到达照记多行，只标注。

## §5 采纳判定：**前端自己算**

**框架不提供任何计算它的 helper、字段或 API**（第 12 节）。它是**派生事实**，随读取时刻变化，一旦框架提供就成为事实上的公开面。所以这段逻辑住下游。

### 5.1 四值定义（第 12 节）

| 取值 | 含义 |
|---|---|
| `ACCEPTED` | 建议动作与该锚点读出的人侧表态**同值** |
| `NOT_ACCEPTED` | **异值**（否决与覆写在此同值，契约不区分） |
| `NOT_COMPARABLE` | 该锚点**有**人侧动作，但它不是表态 |
| `UNDECIDED` | 该锚点**尚无**可读的人侧表态 |

### 5.2 表态比较面

**只认四个动作**：`AGREE` / `REJECT` / `COUNTER_SIGN_AGREE` / `COUNTER_SIGN_REJECT`。

**显式排除**：`RETURN`（退回）· `WITHDRAW`（收回待办）· `INVALID`（作废）· `AUTO_COMPLETE`（自动提交）· `INITIATE_COUNTERSIGN`（发起会签），以及**整个操作注释组**。

### 5.3 判定伪码

```js
// 表态比较面：只有这四个动作参与判定
// 显式排除：RETURN / WITHDRAW / INVALID / AUTO_COMPLETE / INITIATE_COUNTERSIGN
//           以及整个操作注释组
const COMPARE_ACTIONS = ['AGREE', 'REJECT', 'COUNTER_SIGN_AGREE', 'COUNTER_SIGN_REJECT'];

function adoptionOf(evidence, humanAction) {
  if (evidence.outcome !== 'SUGGESTION_PRODUCED') return null; // 本锚点无建议 ⇒ 判定不适用
  if (!humanAction) return 'UNDECIDED';                        // 尚无可读的人侧表态
  if (!COMPARE_ACTIONS.includes(humanAction)) return 'NOT_COMPARABLE';
  return humanAction === evidence.suggestedAction
    ? 'ACCEPTED'        // 同值
    : 'NOT_ACCEPTED';   // 异值（否决与覆写不区分）
}
```

**两点下游需自行处置（ADR 未显式规定，属推论）**：

1. **本锚点无建议时（C / D 列），判定「不适用」** —— 没有可比之值。`null` 与 `UNDECIDED` 不可混用：前者是「没东西可比」，后者是「有建议、人还没表态」。
2. **判定锚在既有读侧槽位，不是「时间上最新」**；**跨锚点不承诺**（第 12 节）。

### 5.4 `AUTO_COMPLETE` 是本机制的**已知边界**，不是可执行的排除规则

读侧契约面**不承载**原始 `CommentType`：`comment` 槽位是业务意见文本、`action` 槽位是映射后动作。`CommentType=AUTO_COMPLETE` 经映射后**表现为面内的 `action=AGREE`**，在无引擎内部类型信息的情况下**不保证**与人工 `AGREE` 可判别（第 12 节）。

**因此**：

- 下游**拿不到** `AUTO_COMPLETE` 这个值 —— 别在代码里写 `if (action === 'AUTO_COMPLETE')`，那是个**永不成立**的分支。
- 同族的第二条边界：动作层 `AGREE` 还有**非评论来源** —— `inferAction` 三级兜底 `deleteReason="completed" → AGREE`。**既无业务意见、也无操作注释**的完成会被读成 `action=AGREE`（第 12 节）。
- 两者都使判定在**同值**时读出 `ACCEPTED`。**修它们要动 core 既有读侧推断语义，越出本机制** —— 登记为已知边界，不在机制内修。

## §6 必须写进 UI 文案的三条边界

1. **`ACCEPTED` ≠ 人接受了建议。** 它只表示**建议动作与人侧表态同值**（见 §5.4）。UI 只能写「建议与人侧表态同值」，**不能**写「已采纳」「AI 建议被采纳」。
2. **证据行数 ≠ 决策次数。** 重复到达照记多行、只标注不抑制（§4）。
3. **「没有建议」有三种成因，不可混为一谈**（第 8 节 / 第 9 节）：**未声明 / 未触发**（关闭状态，**无痕**）· **缺前置的准入失败**（退结构化日志 + 指标，**不落行**）· **结构性写入失败**（锚点失效 / 实例已结束 ⇒ 日志 + 指标）。三者都**不是「失败」**，也都**不是「拒绝」**。审计面的正确读法是三态而非二态。

## §7 不做清单

| 不做 | 依据 |
|---|---|
| **不给建议加「一键采纳」按钮** | 框架不提供从 `suggestedAction` 到流程推进的任何通路（第 5 节）。应用自行消费该值去 `completeTask` 是**应用侧行为、不经框架** |
| **不做「置信度展示 / 风险高亮 / 必须复核才放行」** | 第 12 节明确否决（2,784 人随机实验：干预式设计会把复核变成橡皮图章） |
| **不引入「强制逐条确认」** | 同上 |
| **不把证据渲染成「某人的审批意见」** | `USER_ID_` 为空是**有意为之** —— `ACT_HI_COMMENT.USER_ID_ ≠ 决策证据的真实产出主体`（第 5 节）。通用 UI 的 `author` 为空反而正确 |
| **不自建表 / 不加接口 / 不加缓存** | 单一审计面（第 5 节）；读侧唯一入口 `getApprovalHistory` |
| **不提供撤回动作** | 第 12 节：反悔 = **追加一条相反的人工决定**，不改写历史。注意与流程级的 `WITHDRAW`（收回待办）/ `INVALID`（作废）**同名不同物**，不得合并 |
| **不承诺「覆盖历史」全量可读** | 建议侧**可多条**（外部、异步）；人的决定侧**单槽**（core 既有语义：`comment` 取业务意见组首个）。机制只承诺「该锚点读出的人侧动作 × 该锚点全部建议」（第 12 节） |

## §8 已知空白

| 空白 | 说明 |
|---|---|
| **「列表页显示建议摘要」需要接口配合** | 证据挂审批轨迹 VO，不在任务列表接口里。若列表要显示「本任务有无建议」，需要另行返回摘要 —— 否则只能显示列头而无值。**v1 建议不做**，避免为它加接口 |
| **人侧身份可靠性** | 只承诺**覆盖动作可复核**，**不承诺人侧身份的可靠性**（「不做 / 已知边界」章「人侧身份可靠性」条列为**不修 / 已知边界**）。UI 不得据 `actorId` 做「谁采纳了建议」的强断言 |
| **晚到建议 × 已发生的人工决定** | 允许晚到写入；**不新增 `late` 标注字段 / 状态 / 类型**。读侧按**时间序**呈现，第三方靠时序自行辨别（第 12 节） |
| **失效 / 结束期写入** | 实例结束后 `addComment` 直接抛异常 ⇒ 晚到证据降级为**系统日志 + 指标**，不再作为审批轨迹的一等成员（第 5 节）。UI 上表现为「这条建议不存在」，**不是「失败」** |
| **生命周期** | 删历史实例**级联删**该实例全部评论 ⇒ 证据随实例消失。**当前不承诺比实例活得久**（第 5 节） |
