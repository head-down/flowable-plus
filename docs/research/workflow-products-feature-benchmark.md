# 主流工作流/审批产品功能特性调研

> 调研时间：2026-08-13
> 调研目的：为 flowable-plus 判断「必须补的核心缺失」提供横向参考
> 调研对象：BPMN 引擎（Flowable/Camunda/Activiti）、中式审批产品（钉钉/企微/飞书）、国产 OA（致远/泛微/蓝凌）、国产工作流框架（Warm-Flow）

## 一、按产品分组的特性清单

### 1.1 BPMN 引擎

#### Flowable 6.8.0（本项目基线）/ 7.x

**引擎内核**

- BPMN 2.0 全量支持：用户任务、服务任务、发送任务、接收任务、脚本任务、业务规则任务、HTTP Task（7.x 增强 HEAD/OPTIONS）、手工任务、邮件任务
- 事件支持：启动/结束/边界/中间事件，消息事件、信号事件、错误事件、定时事件、补偿事件、升级事件、条件事件
- 网关：排他（条件）、并行、包容、复杂、事件网关
- 子流程：嵌入式子流程、调用活动（Call Activity）、事件子流程、事务子流程
- 多实例：并行多实例、顺序多实例、嵌套多实例（实现会签/或签/依次审批的底座）
- 定时任务：Timer Start/Intermediate/Catch/Boundary，ISO 8601 周期/持续时间/时间点
- 作业管理：Job、Deadletter Job、Suspended Job、Timer Job、Async Job
- 流程实例挂起/激活（流程定义级与实例级）
- 任务管理：claim（认领）、delegate（委派）、transfer（转办）、resolve（委派回原审批人）、complete、setAssignee、setOwner
- 历史归档：none/activity/audit/full 四档
- IDM：IdentityService 提供用户/组管理（仅引擎内部用，通常对接外部组织架构）
- 流程迁移（Process Migration）：runtimeService.createProcessInstanceMigrationBuilder()，实例迁移到新版本
- 流程定义部署、版本管理（deploymentId + version 字段）
- 批量（Batch）操作：批量启动、批量迁移、批量删除流程实例
- 异步历史（Async History，7.x 默认批量刷盘）
- 事件注册表（Event Registry，7.x 独立模块）

**附加引擎**

- CMMN 1.1 案例引擎
- DMN 1.3 决策引擎（FEEL 表达式，Hit Policy 全支持）
- 表单引擎（6.x 有，7.x 已移除，交给外部低代码平台）
- 内容引擎（6.x 有，7.x 已移除）

**应用/UI**

- Flowable Modeler（6.x AngularJS / 7.x React+ReactFlow 在线设计器）
- Flowable Admin（流程定义/实例/任务管理）
- Flowable IDM（用户/权限管理）
- Flowable Task（任务列表）
- Flowable REST API（OpenAPI 3，7.x 自动生成）

**云原生（7.x）**

- Kubernetes Leader Election、Liveness/Readiness Probe
- Micrometer Prometheus 指标
- GraalVM 原生镜像
- 官方 Helm Chart

#### Camunda 7 / 8

**引擎内核**

- BPMN 2.0 全量支持，与 Flowable 同源（Camunda 7 是 Flowable 5 的 fork 后裔）
- 8.x 改为 Zeebe 流式引擎， hazelcast/弹性集群，不再依赖共享数据库
- 任务：User Task（claim/delegate/transfer）、Service Task（Job Worker 模式）
- 事件、网关、子流程、多实例、定时事件（8.x 改为 Timer Boundary Event + Job）
- 流程实例挂起/激活、迁移（Process Instance Migration）、修改（Process Instance Modification）
- 作业管理：Job、Incident（死信），失败重试可配置
- DMN 1.3 决策引擎（FEEL）
- CMMN 1.1（Camunda 7 有，Camunda 8 暂未实现）
- 表单：Embedded Form（HTML）、Generated Form（基于表单 schema）、Camunda Forms（外置表单引擎）

**应用/UI**

- Camunda Modeler（桌面 + Web Modeler）
- Operate（流程实例运维、Incident 处理）
- Tasklist（任务列表，支持 filter、custom claim）
- Admin（用户/组/权限/租户）
- Cockpit（Camunda 7 监控看板）
- Optimize（商业版，流程效能分析、BI 报表）
- Console（集群/组织管理）

**集成**

- Connectors（HTTP、REST、SOAP、Kafka、AWS Lambda、RPA 等开箱即用连接器）
- Document Handling（文档存储）
- Identity（用户/组/租户，可对接 Keycloak）

#### Activiti 7 / 8

- BPMN 2.0 引擎，社区版迭代缓慢
- Activiti Cloud：Cloud Native 组件（Process Runtime Services、Task Runtime Services、Query Services）
- Activiti Modeler（基于 bpmn.io）
- 多实例、子流程、事件、网关等 BPMN 标准能力
- 任务：claim、delegate、transfer
- 简单的 Application Builder
- 与 Flowable/Camunda 同源，能力大致相同但生态/活跃度落后

### 1.2 中式审批产品

#### 钉钉审批

**审批操作**

- 同意、拒绝、转交、回退（可选节点）、加签（前加签/后加签）、评论、提交、暂存
- 抄送人节点（仅查看/评论，无审核功能）
- 办理人节点（提交/转交/回退/加签/评论）
- 设置审批代理人（按审批类型分别设置，可设代理时间和范围）
- 批量审批（一键批量处理同类待审）
- 催办（发起人主动催办；系统自动催办：即将超时自动提醒）

**多人审批方式**

- 依次审批（最高 20 级）
- 会签（所有人同意才通过）
- 或签（任一同意即通过）
- 投票（满足设定同意人数即通过）

**审批人类型**

- 指定成员、发起人自己、发起人自选、角色、直属主管、部门主管、连续多级主管、部门控件对应主管/角色、表单内联系人

**流程节点类型**

- 发起人节点、审批人节点、抄送人节点、办理人节点、条件分支（且/或、按优先级、最多执行一支）、并行分支（同时流转）、连接器节点、自动化节点

**审批人为空处理**

- 自动通过、自动拒绝、自动转交管理员、转交指定人员

**表单/管理**

- 表单引擎：基础控件 + 控件组（请假/报销/合同等业务联动）
- 表单字段权限：可编辑/只读/隐藏，按节点设置
- 流程版本管理（管理员后台）
- 流程实例管理（数据查询、导出、PDF 下载）
- 流程交接（批量替换审批人 + 待处理单据批量转交）
- 自动审批规则（条件免批，特定条件自动通过）
- 智能审批（AI 识别分类、智能填写、规则自定义、异常提醒、数据分析报告）
- 数据导出、附件容量管理、操作记录
- 多语言、移动端/桌面端

#### 企业微信审批

**审批操作**

- 同意、拒绝、转交、加签（前/后）、回退、撤销（已通过单据可申请撤销）、评论
- 抄送
- 或签、会签
- 批量审批

**审批人类型**

- 上级（默认申请人上级）、标签、单个成员

**流程节点**

- 审批节点、抄送节点、办理节点（隐式）
- 条件分支（按申请人/字段值走不同流程，如金额、请假类型）
- 连续多级上级审批

**表单/管理**

- 内置 20+ 模板（请假、报销、费用等）+ 自定义模板
- 模板字段设置、模板预览
- 启用/停用模板（停用后记录保留）
- 可见范围设置
- 撤销权限、修改权限、节假日同步（请假模板）
- 数据查询（按时间/状态/申请人筛选）、详情查看、PDF 打印、Excel 导出
- API 接口获取审批记录

#### 飞书审批

**审批操作**

- 同意、拒绝、撤回（审批人撤回已同意结果，最后一个节点不支持）、退回（可指定退回范围）、转交、加签、减签、评论
- 抄送（按用户组/角色维度）
- 常用语（审批意见快捷输入）
- 审批意见必填设置
- 代他人提交
- 批量审批

**流程节点**

- 审批节点、抄送节点、办理人节点（财务打款/盖章/归档等）
- 连续多级审批节点（连续多级上级/部门负责人，终点可指定层级或用户组内成员）
- 条件分支（支持日期/联系人/录用/转正控件及控件组作为条件）
- 自动化流程（2024.12+：触发条件 → 自动动作，如审批通过自动发起新审批/发飞书消息）
- 注：并行分支、子流程、自由流程未在更新日志中明确出现

**超时/限时**

- 审批超时自动提醒与关闭（2023.09）
- 限时审批（2025.05，超预设时长自动提醒）

**表单/管理**

- 表单引擎：30+ 控件（明细表格、电话、收款账户、流水号、关联审批、日期、金额、数字、引用多维表格、图片/视频、定位、发票报销控件组、附件等）
- 表单外部数据源、选项关联、控件默认值、批量粘贴、草稿自动保存
- 流程版本管理（2025.06 编辑版本管理）
- 离职交接（手动 + 自动）
- 审批已读/未读标记
- 审批摘要配置、自定义审批编号
- 数据管理与导出
- 团队效率诊断（团队视角审批效率分析）
- 自定义打印模板
- 16 种语言国际化
- 移动端 + 桌面端 + 侧边栏

### 1.3 国产 OA 工作流

> 注：以下基于公开评测与厂商宣传整理，具体功能以厂商最新版本为准。三家均强调"流程引擎"是核心能力之一。

#### 泛微 e-cology

- 流程引擎历史最久，强调"任意管理流程落地"
- 流程分支/分叉、流程套接（流程间引用）
- 流程投票、流程监控、流程干预（管理员强制操作）
- 流程权限控制（数据权限/操作权限）
- AI 智能搭建流程
- 流程报表
- 自由流程（部分支持）
- 自定义表单 + 二次开发工具（平台化）
- 集成中间件 EBS，标准接口触发与回写
- 信创版本

#### 致远互联

- 协同运营中台理念
- 低代码平台 + AI 介入
- 工作流基础能力齐全（具体细节厂商未公开细化）
- 与用友 ERP 集成友好
- 政务/信创市场表现突出
- 渠道商 ERP 背景强，可做深度客开（财务共享、全面预算、供应链协同等）
- 标准化产品 + 业务生成器做个性化开发

#### 蓝凌 MK-N

- BPM 流程引擎（宣传复杂条件判断计算能力，所见即所得）
- 自定义能力强，高度定制化服务
- 知识管理与流程结合
- 信创数智化工作平台 MK-N（2023+，AI 增强 BPM/低代码/KM）
- 自由流程设置有待提升
- 大中型客户群体为主

### 1.4 国产工作流框架

#### Warm-Flow（dromara 社区）

- 7 张表极简设计，国产轻量工作流
- 审批操作：通过、退回、撤销、拿回、任意跳转、终止、转办、票签（或签）、委派、加减签
- 流程模式：互斥（条件分支）、并行、自动审批
- 条件表达式：内置 SpEL + 自定义
- 办理人表达式：${handler} + SpEL
- 监听器：4 种（开始/结束/节点/任务），支持 Spel
- 流程变量、动态权限
- 流程设计器：jar 包快速集成，原生支持经典 + 仿钉钉双模式
- 流程图：自带，支持节点状态颜色，双模式
- ORM 支持：MyBatis/Mybatis-Plus/Jpa/Easy-Query/BeetlSql
- 数据库：MySQL/Oracle/PostgreSQL/SQL Server，可扩展国产库
- 多租户、软删除（引擎自身维护）
- 兼容 Spring/Solon，Java 8/17/21
- 实战项目：基于 Ruoyi-Vue 的封装

## 三、中式审批产品特有而 BPMN 引擎通常不内置的功能

> 这些是钉钉/企微/飞书/国产 OA "开箱即用"但 Flowable/Camunda/Activiti 需要业务层自行实现的功能。

| 功能 | 说明 | 落点建议 |
|---|---|---|
| **抄送人节点** | 流程节点之一，仅通知不审核。BPMN 无原生节点类型，需用 Service Task + 监听器模拟 | 业务层 / 框架可提供抄送 SPI |
| **抄送列表查询** | "我抄送的" / "抄送给我的" 列表 | 业务层（需建表） |
| **催办** | 发起人主动催办 + 系统自动催办（即将超时提醒） | 业务层（基于 Timer + 通知通道） |
| **超时处理（提醒/自动同意/自动拒绝/自动转办）** | 国产审批产品标配。BPMN 引擎有 Timer Boundary 但需自实现策略 | 业务层或框架提供超时策略 SPI |
| **限速（防刷）** | 同一发起人/同一模板单位时间发起次数限制 | 业务层 |
| **批量审批** | 多个待办一次性同意/拒绝 | 业务层（应用层循环调用） |
| **审批代理人** | 休假/出差期间，由代理人代审批。BPMN 有 delegate 但语义是"暂时委派后回到原审批人"，不是"代理期间全部代审批" | 业务层（基于用户代理关系表 + 运行时改 assignee） |
| **审批意见常用语** | 审批意见快捷输入 | 业务层（前端配置） |
| **审批摘要配置** | 待办列表显示哪些字段的摘要 | 业务层 |
| **离职交接** | 待处理单据批量转交 + 在途流程审批人批量替换 | 业务层（管理员干预的封装） |
| **自由流程** | 发起人/审批人运行时动态添加节点。BPMN 流程定义是静态的，自由流程需要运行时改流程模型 | 业务层（不在框架范围） |
| **流程版本管理后台** | 钉钉/飞书提供编辑版本管理。BPMN 引擎有 deployment version 但无后台 UI | 业务层（admin 后台） |
| **流程模板启用/停用** | 模板级别的可见性控制 | 业务层 |
| **表单字段权限（按节点可编辑/只读/隐藏）** | 国产审批产品标配。BPMN 表单引擎不内置此能力 | 业务层（表单引擎层） |
| **表单控件组（请假/报销/合同等业务联动）** | 钉钉特有，控件组与外部业务系统数据同步 | 业务层 |
| **审批人为空处理策略** | 找不到审批人时的兜底（自动通过/拒绝/转交管理员）。BPMN 需自实现 | 业务层或框架可提供 SPI |
| **AI 智能审批** | AI 识别分类、智能填写、规则自定义、数据分析 | 业务层 |
| **数据统计分析/流程报表** | Optimize 在 Camunda 是商业版独立产品。国产 OA 标配 | 业务层（BI 报表） |

## 四、BPMN 引擎内置但中式产品通常没有的功能

| 功能 | 说明 |
|---|---|
| **BPMN 全量事件模型** | 消息事件、信号事件、补偿事件、升级事件、条件事件 — 中式审批产品通常只有"自动触发"和"超时" |
| **CMMN 案例引擎** | 面向非结构化案例管理，中式产品不内置 |
| **DMN 决策引擎** | 业务规则表，中式产品通常用"条件分支"代替 |
| **事件注册表（Event Registry）** | Flowable 7.x 独立模块，跨流程事件订阅 |
| **包容网关** | 中式产品通常只有"条件分支"和"并行分支"，无包容（条件满足的分支并行执行） |
| **事务子流程 + 补偿事件** | 长事务与回滚，中式产品不内置 |
| **调用活动（Call Activity）** | 跨流程定义复用，中式产品不内置 |
| **复杂网关** | 中式产品不内置 |
| **流程实例迁移（Process Migration）** | 实例从旧版本流程定义迁移到新版本，BPMN 引擎原生支持，中式产品不支持 |
| **流程实例修改（Process Modification）** | Camunda 支持运行时移动活动节点，中式产品不支持 |
| **死信任务 / Incident** | 失败作业的独立管理与重试，中式产品不内置 |
| **多引擎裁剪（BPMN/CMMN/DMN 独立）** | Flowable/Camunda 支持，中式产品不支持 |
| **集群 / 云原生（K8s Leader Election、Probe）** | BPMN 引擎原生，中式产品是 SaaS |
| **REST API / OpenAPI** | BPMN 引擎原生，中式产品通过 OpenAPI 暴露部分能力 |
| **批处理（Batch）** | 批量启动/迁移/删除流程实例，中式产品不支持 |
| **异步历史（Async History）** | Flowable 7.x 性能优化，中式产品不内置 |

## 五、flowable-plus 缺失分析与建议

### 5.1 必须补的核心缺失（与钉钉/企微/飞书对比）

> 判据：中式审批场景的高频需求 + Flowable 引擎未内置 + 框架层（脱离具体业务也能成立）应该提供

| 缺失项 | 优先级 | 落点 | 理由 |
|---|---|---|---|
| **抄送能力** | 高 | core 提供抄送 SPI（抄送人解析 + 抄送记录），业务层建表 | 钉钉/企微/飞书/国产 OA 全部标配，所有中式审批场景都需要。框架层提供"抄送人解析 + 抄送事件"即可，记录存储仍由业务层 |
| **超时处理策略** | 高 | core 提供超时策略 SPI（提醒/自动同意/自动拒绝/自动转办） | 中式审批强需求。Flowable 有 Timer Boundary 但需要业务层决定超时后做什么，框架可提供策略接口 |
| **催办** | 中 | core 提供催办入口 + 通知 SPI | 中式审批高频操作。框架提供"催办动作 + 通知发送"接口，通知通道由业务层注入 |
| **审批人为空处理策略** | 中 | core 提供空审批人策略 SPI | 钉钉/企微/飞书全部标配（自动通过/拒绝/转交管理员）。框架提供策略接口，默认实现可基于 Flowable 的任务 assignee 为空时触发 |
| **管理员干预（管理员强制操作）** | 中 | core 提供管理员操作便利接口（终止/转交/批量转交） | 中式审批运维场景需要。Flowable 有 deleteProcessInstance/moveActivityIdsToSingleActivityId，但 API 不直观，框架可封装 |
| **流程实例挂起/激活便利接口** | 中 | core 提供便利接口 | Flowable 原生能力，但 API 散在 runtimeService，框架封装为门面方法即可 |

### 5.2 可选增强（视使用方反馈再补）

| 项 | 落点 | 理由 |
|---|---|---|
| **批量审批便利接口** | core 提供批量 complete 入口 | 业务层循环调用即可，但框架提供批量入口可统一事件、统一权限校验 |
| **审批代理人** | core 提供代理关系解析 SPI | 业务层可自实现，框架提供 SPI 让代理关系可注入 |
| **数据权限回调增强** | core 已有回调扩展（ADR-0007），可补充常用实现 | 视多项目使用情况触发（见已有 memory） |
| **流程迁移便利接口** | core 提供 MigrationBuilder 薄壳 | Flowable 原生能力，但 API 复杂，框架可封装常见迁移场景 |
| **限速（防刷）** | 不建议进框架 | 业务层用 Redis/RateLimiter 即可，与流程引擎解耦 |
| **定时任务便利封装** | core 提供 Timer 设置便利接口 | Flowable 原生 BPMN 即可，框架仅做语法糖 |

### 5.3 不该进框架（属于业务层）

| 项 | 理由 |
|---|---|
| **表单引擎 / 表单字段权限** | 表单是业务数据的载体，脱离业务数据无意义（ADR-0032）。钉钉/飞书的表单引擎是产品级能力，不是框架层 |
| **表单控件组（请假/报销/合同业务联动）** | 纯业务领域知识 |
| **AI 智能审批** | 业务层 AI 能力，与流程引擎解耦 |
| **数据统计/流程报表/BI** | 报表层独立于引擎，Camunda Optimize 也是独立产品 |
| **自由流程（运行时动态加节点）** | 流程定义静态是 BPMN 的核心约束，自由流程本质是另一套模型。建议业务层基于状态机自实现，不要硬塞进 BPMN |
| **流程版本管理后台 UI** | admin 后台属于应用层 |
| **流程模板启用/停用** | 应用层配置 |
| **离职交接 UI** | 应用层 |
| **审批意见常用语** | 前端配置 |
| **审批摘要配置** | 前端配置 |
| **消息通知通道（钉钉/企微/飞书/邮件/短信）** | 通知通道是基础设施，框架只发事件，通道由业务层接入 |
| **租户隔离的具体实现** | Flowable 原生 tenantId 已足够，具体租户管理是应用层 |
| **健康检查 / Prometheus 监控** | 运维基础设施层，Spring Boot Actuator 即可 |

### 5.4 总结一句话

flowable-plus 当前已覆盖**审批操作类**（A）的绝大部分中式能力（发起/同意/驳回/撤回/撤销/跳转/转办/委托/加签/减签/会签/或签），这与项目定位「中式审批简化 API」高度吻合。

下一步应补的"必须项"集中在 **B 审批高级** 中的**抄送、超时处理、催办、审批人为空处理**四项 —— 这些是中式审批产品全部标配而 Flowable 引擎不内置的能力，且都能在框架层以 SPI 形式提供（脱离具体业务也成立）。

**管理能力**（D）中的管理员干预、流程实例挂起/激活便利接口属于"Flowable 原生但 API 不直观"的封装，优先级中。

**表单引擎、AI 审批、自由流程、统计报表**等明确属于业务层，不应进框架（与 ADR-0029、ADR-0032 一致）。
